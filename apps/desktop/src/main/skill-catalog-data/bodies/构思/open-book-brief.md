# 开书前先把方向钉死

改编自 zenstory-ai/oh-story-claudecode 的 story-long-write（开书的一次性问答，MIT）。只搬方法，不搬原文。

开书的时候最容易省掉的一步，是先把「这本书到底是什么」想清楚就开始写第一卷。
结果写到第二十几章才发现：主线其实没定，主角想要什么也没定，
于是后面每一章都是在给一个没定型的故事打补丁。

## 一次只问一个

不要一次抛出「题材？主角？冲突？篇幅？」四连问——人会挑最容易答的那个答，
剩下的三个等于没问。**一次问一个，等回答，追问，再问下一个。**

## 四问，顺序不能换

### 一、写给谁

具体到一个人。不是「写给年轻人」，是「一个每天通勤路上读、读三章就睡的人」。
写给谁定了，句子长短才有着落——通勤读者与睡前读者的耐心完全不同。

### 二、这本书要解决什么

用一句话说出来，且这句话里必须有一个人物和一个障碍。
说不出来 ⇒ 这本书还没有主心骨，先别排章节。

### 三、写到哪儿算完

给一个**可数的**终点：多少章、主角变成什么样、有没有一个具体的东西被解决或被毁掉。
「写完整个故事」不是终点，那是无限。

### 四、明确不写什么

这一条最容易被跳过，也最省事。
写下来：这本书**不做**什么（不写回忆杀 / 不让主角死 / 不引入系统面板）。
每往后加一条，后面要推翻它的次数就少一半。

## 钉完之后

把这四行写进这本书的大纲。**之后每开一章之前，把它拿出来对一遍。**
对不上就停下来问自己：这一章在往「写给谁 / 解决什么 / 终点 / 不写什么」哪一条上靠？
哪条都不靠 ⇒ 这一章是凑字数的。

## 答不上来的时候

- 答不出「写给谁」⇒ 先别写，读者还没找到。
- 答不出「要解决什么」⇒ 回去答第二问，不要用「先写着看看」糊过去。
- 答不出「写到哪算完」⇒ 写一个临时答案，**并明确写上这是临时的**。
  临时答案不许悄悄变成永久答案——它在纸上写着，作者自己会记得改。

## 不要做的事

- 不要在开书阶段顺手写正文。手一痒就写前三章，之后那四条就再也钉不住了。
- 不要一次想一整卷。四问管的是整本书，分卷是后面的事。
- 不要接受「都写一点」这种回答——那是没有答案的另一种说法。
