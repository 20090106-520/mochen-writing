# 第一次读的人会卡在哪

改编自 zenstory-ai/oh-story-claudecode 的 story-review（MIT）。只搬方法，不搬原文。

## 换个身份读

作者读自己的稿子会**自动补全**：知道这个人物是谁、知道三天前发生过什么、
知道那句话是双关。所以作者读自己的稿子几乎读不出问题——**他不是在读，他是在回忆。**

这一份技能只做一件事：读的时候**只允许自己知道正文里写出来的东西**。
不知道的，就当作不知道。卡住的地方全部记下来。

## 记三样，不记评价

读到某一段时脑子里冒出的话，记下来：

- **「等等」**——刚才没看懂什么？（设定跳了、人物身份不清、指代不明）
- **「所以呢」**——然后呢？（这一段没有推事情）
- **「还没完？」**——怎么又来一段？（节奏断了）

**只记这三样，不记「这段写得好不好」。** 好不好是读感，
而读感会随着刚写完时的兴奋状态波动，量不出来。

## 读的过程中顺手做两件事

### 一、标出「第二次解释」

有些信息作者会解释两遍：一遍在人物心里，一遍在叙述里。
第一次是必要的，第二次就是**替读者把他已经懂的事又说了一遍**。
读到时心里冒出「这句刚才说过了」，就标下来。

### 二、标出「只出现一次的专名」

一个只出现一次的人名、地名、称呼——读者要为一个再也不出现的东西付一次记忆成本。
**要么让它再出现一次，要么第一次就别给名字**（用「掌柜」「那位先生」代替）。

## 读完之后

把记下来的三样按章排一遍，**按出现次数排序**：卡得最多的是最该改的。

改的时候注意顺序：
先改「等等」（读不懂的，是硬伤），
再改「所以呢」（不推事情的，是虚的），
最后才动「还没完」（节奏问题，多半改结构，急不来）。

## 不要做的事

- 不要边读边改。读和改要分开两遍——边读边改会只改到最扎眼的那处，
  后面几十处就过去了。
- 不要因为「我知道这些」而替读者开脱。**读者不知道，就是不知道。**
- 不要把「我看不懂」直接等同于「要改」。有些不懂是刻意的。
  判据是：这一处不懂，读者会不会因此**不想往下看**。
