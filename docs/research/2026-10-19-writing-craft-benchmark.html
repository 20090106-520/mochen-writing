横向对比评估 · 只读盘点 + 外部调研

深渊写作 · 人味写作体系横向对比评估

评估对象：写作方法 · 功能 · 人类写作手法 · 字眼算法 · 自研框架 —— 现状是否需要修改
口径：以本仓代码与台账为「现状」，与外部开源实现、学术证据、平台公开政策逐项对照
日期：2026-10-19 ｜ 结论不含任何效果实测读数

核心结论

1

自研框架的骨架合格，不需要推翻

「生成端常驻段 ↔ 扫描端判据单一真身 ↔ 退稿闸只收写死上限的条目」这套架构， 与外部同行（oh-story deslop 的三层诊断 + blocking/advisory 分级）同向且更克制。 要改的是校准方式与判据之外的杠杆，不是分层本身。

2

最大风险：本仓判据与平台判据不同源

本仓是「词表 + 启发式阈值」，平台与检测器是「统计特征 + 分类模型」。 本仓自己的四稿 A/B 已经实测到这一点：词表命中 0/0 的四份稿， 外部读数仍从 0% 走到 100%。因此「继续往词表里加套话词」边际收益最低。

3

三个最高价值的补口，本仓目前一个都没有

① 阈值改由真人语料分位校准（上游已有先例与数字）； ② 一次生成多稿 + 用本仓判据择优（本仓已有 startTurn 通路，改动量小）； ③ 把技能库已有的《文风手册》真正接进生成端（零新依赖）。

三、逐项评估：要不要改

3.1 保留 · 不动（3 项）

  • 六段常驻的分工与单一真身纪律。「生成端说什么、扫描端就能扫什么」「同一件事不留第二份实现」 「不能机器判的不硬上正则」这三条，与外部最优实现（oh-story 的诊断权与改写授权分离、 blocking/advisory 分级）同向，且本仓更克制。
  • 退稿闸的五条独立理由。词命中 / 起手 / 长短 / 结构上限 / 复读各拦各的， 互不代言——这正是外部实现常缺的一层（多把判据揉成一个总分）。
  • 「不把外部检测器读数当结论」。已被外部证据支持：改写反而更易被检出 （arXiv 2610.03110），主流检测器自身也已弃用困惑度+突发度 （GPTZero 2023 秋起改深度学习）。本仓这条纪律是对的，应写得更显眼。

3.2 微调 · 改现有（5 项，按价值排序）

  1. 阈值改用真人语料分位校准（P0）。 做法：取本仓已有真机产物与真机语料（若有）作对照集，逐条统计命中分布， 把 2 / 1 / 5 / 3 这四枚经验值换成「真人分位 + 误报率」； 并在每个常量处标注「依据 = 某语料某分位 / 误报 x%」。上游已有可复制的流程与数字。
    风险提示：偏严的阈值会误退大量真人网文——Liang 等研究显示检测器对正式人类文本误报率高达 61.3%。
  2. 结构上限从绝对数改为每千字（P1）。 现状「一章最多三处对话标签」在长章上会误伤、在短章上过松。上游统一按 per-kilo。 本仓台账 §一百三十 自己已留了这条口子：「若真机发现长章被误伤，再按每千字重估」。
  3. 补「用笔层」的处置动作（P1）。 生成端已有「动作拆节拍」等叮嘱，但缺「详略三测（删除 / 压缩 / 展开）」与 「章末最后一拍」这两条上游成法——技能库已有对应文本，接常驻即可。
  4. 判据分 blocking / advisory 两级（P2）。 现状只有「进闸 / 不进闸」二元。外部把 20+ 类判据分两档处置， 可减少「闸是文风警察」的误伤面，也给体检报告更好的优先级。
  5. 补修辞密度扫描判据（P2）。 对偶 / 排比 / 比喻的密度在中文上有实测支撑（AI 显著高于人类）， 比「破折号」这类被证伪的表层特征可靠。

3.3 新增 · 本仓空缺（4 项，按价值排序）

  1. 多稿采样 + 本仓判据优选（P0）。 同一场戏一次生成 N 稿，用本仓已有判据（spread / 起手 / 复读 / 命中）+ 可选的外部方向读数择优。 依据：本仓四稿 A/B 已证明「单点改动（对话）→ 读数 59%→100%」， 而 best-of-N 正是把这种「撞对一次」变成稳定机制的办法。 通路现成：window.mochen.startTurn，无需新依赖。
  2. 作者本人风格档案接进生成端（P0）。 技能库已有《给这本书立一本文风手册》（六维拆法），但当前只是「挂入才生效」的用户技能， 默认那一轮模型看不见。把它下沉成动态段：从本书已完稿章节里现抽六维摘要注入。 这是外部前沿（风格指纹注入 / 模仿作者旧稿）中最容易低成本落地的一条。
  3. 量化指标层（P1）。 本仓无模型概率，可用代理指标：字符级 n-gram 困惑度、句长突发度、词多样性（type-token ratio）。 用途只有一个——作为「改稿前后哪版更活」的相对比较，不作绝对判据。
  4. 退化专项检测（P1）。 补「电报体 / 短碎句 / 虚词被扫光」这一类：删得过狠会写出另一种机器味， 本仓目前只有「复读」一条退化判据。
不建议做的两件事。 ① 继续扩词表：本仓四稿实测已显示词表命中 0 与检测器读数 0% 可以并存， 删词对平台判 DA 的直接作用无证据支持； ② 为「过审」而伪造原创度或对抗式改写：改写会提高词汇多样性、反而更易被分类模型识别（arXiv 2610.03110）， 且与平台合规要求（AI 内容标识）相冲突。

四、优先建议

P0
三件事，都零新依赖、都在本仓既有结构上做。 ① 阈值真人语料校准（把 10 条经验值变成有依据的值 + 标注误报率）； ② 多稿采样 + 判据优选（复用 startTurn 通路）； ③ 作者风格档案下沉为动态段（复用技能库已有的六维拆法）。
P1
④ 结构上限改 per-kilo；⑤ 补用笔层（详略三测 / 章末最后一拍）； ⑥ 量化指标代理层（n-gram 困惑度 / 突发度 / 词多样性）； ⑦ 退化专项（电报体 / 短碎句）。
P2
⑧ 判据分 blocking / advisory；⑨ 补修辞密度扫描判据； ⑩ 解码控制（logit bias 等，取决于供应商是否开放该参数）。

五、局限与未证实

  • 平台算法不公开。番茄 / 起点 / 晋江的具体检测算法与阈值均未公开，本报告只能到「机制层面」（AI 检测 + 人工编辑 + 低质模型 + 合规标识四层叠加）为止。
  • 朱雀读数未证实。「140 万样本、准确率 >92%」来自第三方转述，未见腾讯官方技术文档；「困惑度+突发度」描述来自用户博客。本仓既有纪律（不采信）因此是恰当的。
  • 本报告未做任何实测。全部为代码盘点 + 外部资料对照 + 逻辑推理，不包含改稿前后的读数对比，也不预测任何改造的收益幅度。
  • 部分上游项目未能核实。YuppyChen/novelist-test 被本仓记为「风格拆书流程」，但该仓库署名 skill 实为叙事分析透镜；LikC1606/deep-research-skill 未检索到同名仓库。这两条来源可靠性存疑，涉及它们的既有技能文本建议复核出处。
  • 「自研框架」的口径。本报告按「分层提示词装配 + 扫描判据体系 + 技能库 + 档案」这一整体理解；若你指的另有具体所指（如某个独立模块），结论需按该模块重新核对。
