# 作者风格档案下沉（P0-③ · 2026-10-19）

## 一、这一刀要收的是什么

技能库里早就有一本《给这本书立一本文风手册》（`apps/desktop/src/main/skill-catalog-style.ts`，`dirName: style-handbook`），
它给的是**六维拆法**——① 句子长度 ② 标点脾气 ③ 叙述距离 ④ 对白与叙述的比例 ⑤ 每段的收法
⑥ 硬碰硬的地方怎么写（写情绪还是写动作）。但它现在是一枚**只有用户手动挂进技能栏才生效**的技能：
默认那一轮模型看不见它，于是长篇最常见的退化照旧发生——**每一章都在「写好」，每一章都不像前面那些章**。

这一刀把它的**可量化那半边**下沉为生成端的常驻动态段（与 `bookFlavorSentence` / `openingsSentence` /
`dialogueBalanceSentence` 同构）：从 `assembled.items` 里 `kind === "chapter"` 的正文现算一份「本书腔调摘要」，
写新内容时对着它走。零新依赖。

### 与既有三段的区别（为什么不是重复叮嘱）

- `bookFlavorSentence`：把书里**用滥的**写法点名，叮嘱**避开**（向下拉）。
- `openingsSentence`：把各章**起手式**点名，叮嘱**换进法**（防流水线）。
- `dialogueBalanceSentence`：只在这一章**过密／全叙述**时出声（异常提醒）。
- 本段：把这本书**自己的常态**（句长、标点、对白比例、段末收法）报出来，叮嘱**保持**（防漂移）。
  常态不吭声的三段管不着「这一章和前二十章不像」这件事。

### 六维里能落几维（如实）

| 维 | 能否实测 | 落点 |
| --- | --- | --- |
| ① 句子长度 | 能 | 复用 `sentenceRhythmOf`（体检与退稿闸同一真身） |
| ② 标点脾气 | 能 | 新增：破折号／分号／省略号**每千字**密度 |
| ③ 叙述距离 | **不能** | 要读叙述者与人物的信息落差才判得准——**只写进 spec 理由，不上机器判** |
| ④ 对白与叙述比例 | 能 | 复用 `dialogueBalance`（体检第六类同一真身） |
| ⑤ 每段的收法 | 能（启发式） | 新增：段末是否仍在引号内（`endsInsideQuote`） |
| ⑥ 硬碰硬处怎么写 | **不能** | 语义判断，同上不硬上正则 |

③⑥ 两维量不出来，**不硬凑**：摘要段如实说这两样「本段不报，按前文自己的写法来」（§一百零五 既定取舍）。

## 二、纪律

1. **先红后绿**（TDD）：判据先写成红的，再动实现。
2. **单一真身**：句长与对白占比**复用**既有函数，不在新文件里重算一遍；引号配对规则只住 `dialogue.ts` 一处。
3. **本段不是判据、不进闸**：它是给模型看的**读物**（这本书的常态读数），不是「超标即拦」的判据——
   因此**不同批补扫描端判据**，也不进 `AI_FLAVOR_STRUCTURE_GATED_LABELS`。铁律「生成端说什么、扫描端就能扫什么」
   约束的是**能机器判的约束**；这里是描述性统计，理由写在本节。
4. **硬约束优先**：摘要说的是「这本书的习惯」，与文风硬约束（禁从句式、结构上限）冲突时**硬约束优先**——
   这一句必须写进段里，否则模型会拿「本书习惯」当免死金牌。
5. **同批修一处召回裂缝**（见 §三.1）：对白占比与段末收法都靠引号配对，而现有真身
   `dialogueBalance` **只认全角 `「」『』`**。§一百三十一 的真机复验已经查明**出厂主笔实际产出用半角直引号 `"`**——
   照原样落地，摘要会把一本对白充裕的书报成「对白占比约 0%」，**主动误导模型**。故本刀同批把这处配对补齐。
6. **不推送**：只在本地提交（沿用 §一百三十／一百三十一 用户叫停）。
7. **零新依赖**：不引任何包，不新增 IO。

## 三、改法（精确到文件与常量）

### 1) `packages/contracts/src/dialogue.ts`（配对真身补齐 + 一处共用）

- 新增模块内私有的 `scanQuotes(text, visit)`：**唯一的引号配对实现**，
  逐字符回调 `(char, inside)`；引号字符本身不进回调（与旧实现「引号不计入 total」等效）。
  - 全角 `「『` 开、`」』` 闭（带深度，防嵌套串味——旧口径一字不动）；
  - 弯引号 `“` 开、`”` 闭；
  - 半角 `"` 开闭同形 → **行内奇偶**判定（奇数个为开）；**行末回落**（该行不成对的那个不污染后文）——
    与 `ai-flavor.ts` 的 `normalizeDialogueQuotes()` 同一路数（那里为**句式匹配**归一，这里为**字数统计**配对，各司其职）。
- `dialogueBalance` 改为走 `scanQuotes`，`total`／`quoted` 口径与阈值**逐字不变**（「」稿读数与旧实现完全一致）。
- 新增导出 `endsInsideQuote(paragraph): boolean`：这段文字读完是否仍停在引号内（段末收法用）。
- 文件头注释补两句：半角／弯引号进入配对；`endsInsideQuote` 与占比同吃一份配对。

### 2) `packages/contracts/src/style-profile.ts`（新增，测量真身）

- `STYLE_PROFILE_MIN_CHARS = 500`：装入上下文的正文**非空白字数**不足这个数不立手册
  （技能原文：**不要在开书之前立手册**——没有样本可拆，立出来的只能是别人的东西）。
- `STYLE_PROFILE_PUNCTUATION`：`破折号 ——`／`分号 ；`／`省略号 ……`（每千字密度；单个 `—`／`…` 不单列，
  本书产出为成对）。
- `interface StyleProfile`：`charCount`／`rhythm`（`SentenceRhythm | null`）／`punctuation`（三条每千字，1 位小数）
  ／`dialogueRatio`／`endsOnQuote: { count, total }`。
- `styleProfileOf(contents: readonly string[]): StyleProfile | null`：
  先 `dialogueBalance(全文).total` 取非空白字数（**同一口径、不重算**）→ 不足 500 返回 `null`；
  再 `sentenceRhythmOf(全文)`（不足 10 句为 `null`，该维不报）；标点按 `split(mark).length - 1` 计；
  段末收法按**非空行**＝一段，逐段 `endsInsideQuote`。
- 文件头写清：本文件只放**测量**，说成人话那一段住 `prompt-assembly.ts`（与 `dialogue.ts` / `dialogueBalanceSentence` 同一分工）。

### 3) `packages/contracts/src/index.ts`

- `export * from "./style-profile.js";`（紧邻 `./dialogue.js`）。

### 4) `apps/desktop/src/main/prompt-assembly.ts`（说成人话的那一段）

- 新增 `styleProfileSentence(assembled: AssembledContext): string`：
  取 `kind === "chapter"` 条目的正文拼起来喂 `styleProfileOf`；`null`（样本不足）返回**空串**（不注入空段）。
- 措辞（点名的四维＋两句纪律）：

  > 本书腔调摘要（从已完稿正文实测；这是这本书自己的习惯，不是「优秀小说该有的样子」）：
  > 句子平均 X 字、句长波动 Y（0.9 上下算有起伏，0.3 以下偏匀）；标点脾气：破折号 A/千字、分号 B/千字、省略号 C/千字；
  > 对白约占 P%（引号内字数）；收在台词上的段落 K/L 段。
  > 写新内容时**保持同一腔调**——句长别忽然整齐、标点别忽然换一套、对白比例别大幅偏离；
  > 写完拿这几条对一遍，对不上的先分清是「这一章不适合这条（那就算一次例外）」还是「跑偏了」。
  > 与上面的文风硬约束冲突时**硬约束优先**：那是下限，这条只是这本书自己的习惯。
  > 叙述距离、冲突戏写情绪还是写动作，这两样读不出来，本段不报——按前文自己的写法来。

  （`rhythm === null` 时省掉句长那半句；`endsOnQuote.total === 0` 时省掉段末那半句。）
- 装配数组：**紧接 `dialogueBalanceSentence` 那一段之后**（同样是「本书现场」类动态段，与三段并列）。

### 5) 不改动的既有判定（回读确认）

- `AI_FLAVOR_INSTRUCTION` … `HUMAN_DIALOGUE_INSTRUCTION` **六段常驻一字不动**；
- `bookFlavorSentence` / `openingsSentence` / `dialogueBalanceSentence` 的措辞与判线**一字不动**
  （`dialogueBalance` 走新配对后，`「」` 稿读数不变；半角 `"` 稿从「读不出来」变成「读得出来」——那是修正）；
- 扫描端 `ai-flavor.ts` 的词表、六条正则、四条统计函数、闸阈值、退稿闸 `doc-tools-host.ts`：**一字不动**；
- 体检八类：**一字不动**（第六类从改动中受益，非回归）。

## 四、验收（AC）

1. 先红：新用例跑出失败（契约里没有 `styleProfileOf` / `endsInsideQuote`；提示词里没有「本书腔调摘要」）。
2. 后绿：`corepack pnpm verify` 全绿（prettier → 6 枚 tsc → eslint → 边界 → 行数预算 → vitest → `VERIFY_EXIT=0`）。
3. 提示词到位：跑 `defaultPromptFor` 读回，摘要段在 `对话写法要求` 之后、联网段之前；
   样本不足、或只有非 `chapter` 条目时**整段不出现**。
4. 邻近守卫全绿：既有对话占比用例（`「」` 稿过密／全叙述／常态／过短）与喂 `"` 稿的存量读数，逐条核对。
5. 收口（**按用户要求只到本地**）：commit（不 push）→ 工作树干净 → 仓外临时件清零。
6. 台账 `docs/superpowers/plans/2026-10-09-full-scan-report.md` 补记 §一百三十二。

## 五、未收口（如实留档）

- **③⑥ 两维不落机器判**：叙述距离、冲突戏写情绪还是动作，要读整章的语义与信息落差才判得准——
  按 §一百零五 取舍只写生成端（摘要里如实说「本段不报」），不上正则。
- **标点只数三样**：破折号／分号／省略号是技能原文点名的三样；其他标点（问号／感叹号／括号）不数，
  数了也说不成一句有用的叮嘱。
- **段末收法是启发式**：以「非空行 = 一段」为口径（本仓产出的章节正文即行式段落）；段内不闭合的引号会被判成
  「收在台词上」——那正是它要抓的形态。极端排版的稿子（一行多段）会失真，不为此加复杂度。
- **半角引号配对是行内奇偶启发式**：真「不配对」的半角引号（英文引号嵌在中文里）会有一行读偏；
  不为此上更重的解析——收益不抵票据（与 §一百三十一 T7.7 同一取舍）。
- **效果只能真机目检**：摘要读数对不对，靠作者拿一章对照前文看；外部检测器读数不作结论依据（项目记忆）。
- **不推送**（用户叫停）：README 门禁节不换绑、CI 不读；因此本刀没有 CI 读数，这是有意为之。
