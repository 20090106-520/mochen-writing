# 用笔处置（五）：详略三测 ＋ 章末最后一拍（2026-10-20）

## 一、这一刀要收的是什么

来源是外部调研报告（`docs/research/2026-10-19-writing-craft-benchmark.html`）P1 价值序里的
**⑤ 补「用笔层」的处置动作**：报告第 503-509 行按「三层诊断（表达层 / 用笔层 / 故事层）」对比本仓做法，
指出本仓有**表达层**（句式正则 ＋ 手法叮嘱）却缺**用笔层**（详略·删除测试）；第 616-620 行点名两条
上游成法——「**详略三测（删除／压缩／展开）**」与「**章末最后一拍**」，并称「技能库已有对应文本，
接常驻即可」。

### 报告这条前提不成立（本刀因此是「新写」，不是「接线」）

全仓 grep「详略三测」「章末最后一拍」**只命中报告自身**（另有两处 `useTrailingValue.test.ts` /
`usePreviewDraft.test.ts` 里的「最后一拍」是 debounce 的比喻，与本条无关）——技能库里**没有**这两段原文。
所以本刀是**新写这两段生成端指导文本、按同形接常驻**，不是把既有技能文本接上线。

### 与既有六段常驻的分工（互补，不冲突）

| 段 | 管什么 |
| --- | --- |
| `AI_FLAVOR_INSTRUCTION` | 词与句（词表 ＋ 认知转述 ＋ 副词 ＋ 句长错落） |
| `DE_AI_FLAVOR_STRUCTURE_INSTRUCTION` | 结构级机器味（破折号／排比／对偶／明喻／抽象主语／**章末四禁**／开篇／引号加戏／反差模板／打转） |
| `QUALITY_INSTRUCTION` | 落到哪个感官、用哪个具体名词、对话节拍、续写衔接 |
| `NARRATIVE_CRAFT_INSTRUCTION` | 一段叙述怎么展开（演情绪／拆节拍／环境映心情／过渡锚／快慢分） |
| `HUMAN_CRAFT_INSTRUCTION` | 一场戏成立不成立（逻辑／有事件／细节取舍／语言观） |
| `HUMAN_DIALOGUE_INSTRUCTION` | 对话怎么写（标签上限／闲话跑题／说错改口／段落打散） |
| **本刀新段** | **对一段给定文字做处置**（删／压／展三道测试）＋ **章末落在哪一拍**（正向） |

三条边界写清楚：

1. **「详略三测」是过程，不是口号**：既有 `NARRATIVE_CRAFT` ⑤「快慢要分」与 `HUMAN_CRAFT` ③
   「该慢的多写两拍／该省的直接跳」管的是**感受层面的节拍**；本刀补的是**对每一段跑一遍的处置动作**
   （先删→再压→该展的展），与技能库 `deslop-structure`「改 AI 味先判删」的**删除优先**、以及它那条
   **电报体自检**同一口径——技能是「用户挂入才生效」，本刀把最要紧的这两条折成常驻。
2. **「章末最后一拍」与「章末四禁」互补**：四禁是**负向**（不许总结／升华／哲理／伏笔预告）；
   本刀是**正向**（这一拍该落在哪、该动什么），两条合起来才是完整的章末口径。
3. **不重叠叮嘱**：既有六段**一字不动**。

### 不新增扫描端判据（§一百零五 既定取舍）

两条都要读**整章上下文**才判得准——「这一段能不能删」判的是它与伏笔／钩子／人物特征／情节推进的
关系，「最后一拍动没动」判的是它与本章前文的关系，都不是正则扫得动的。所以**只进生成端、不上扫描判据**、
**不设进闸**，与 `packages/contracts/src/ai-flavor.ts` 既有「结构级三类不硬上正则、留给人工判读」同一取舍。

### 不写任何数值上限（本仓「不编数」纪律）

生成端写明数值上限的判据才进退稿闸（铁律）；这两个成法都不写数字——写「一章最多删几段」没有依据，
且要写成数就得与扫描端同一份真身对齐，而本刀不上扫描。所以**新段通篇无数字上限**
（「三言两语」「多写两拍」是中文习语／与既有段同形的软说法，不是起报线）。

## 二、纪律

1. **先红后绿**（TDD）：判据先写成红的，再动实现。
2. **既有六段常驻一字不动**、装配顺序前六段位置不变。
3. **不改扫描端**：`packages/contracts/src/ai-flavor.ts` 本刀一行不动。
4. **用户叫停推送**：本刀只在本地提交，**不 push、不换绑 README 门禁、不读 CI**。

## 三、改法（精确到文件与常量）

### 唯一改动点：`apps/desktop/src/main/prompt-assembly.ts`

新增常驻常量 `DETAIL_AND_BEAT_INSTRUCTION`（两条，照旧给**可执行判据**，不空喊「写得有详有略」）：

1. **详略三测**——对每一段（写的时候／改稿时）跑三道测试，按答案处置：
   - **删**：去掉这段／这句，伏笔、钩子、人物特征、情节推进会不会丢？一样不丢就删掉——多半是解释、
     注水、复述刚发生的事。
   - **压**：删不掉就再问能不能一句概括掉，只留最关键的那一拍（动作/信息越少，留下的那几个越显眼）。
   - **展**：戏眼、情绪的转折点、人物做决定的那个瞬间反倒要展开——一笔带过就是把该给读者的东西省了；
     在那里多写两拍。
   - **度**：删与压要留分寸——删的是废话，不是中文的自然冗余；虚词扫光、每个动作挂「了一下」的尾巴、
     整段只剩最短句，那是**电报体**，读起来像另一台机器写的。
2. **章末最后一拍**——章尾停在哪，是这一章最后拍下的一格画面：
   - 这一拍要**落在本章已经建立起来的东西上**（一个具体动作、一句话、一件没接完的物件），
     且它得让处境／关系／读者的悬念**动一下**；
   - **不在章尾开新线**（抛一个前文没提过的悬念、冒出一个没出现过的人）——那是把线头挂在那儿，
     不是收束；也别把这一拍写成总结或感叹（**章末四禁**另外管这个）；
   - 写完先想清「最后一拍是什么」，写不到就回头改。

落点：`defaultPromptFor` 装配数组里**紧接 `HUMAN_DIALOGUE_INSTRUCTION` 之后**、
在动态段（`bookFlavor` 起）之前。

## 四、验收（AC）

1. 先红：新判据跑出失败（`defaultPromptFor` 读回缺新段）。
2. 后绿：`corepack pnpm verify` 全绿（prettier → tsc → eslint → 边界 → 行数预算 → vitest → `VERIFY_EXIT=0`）。
3. 提示词到位：跑 `defaultPromptFor` 读回，新段在 `HUMAN_DIALOGUE_INSTRUCTION` 之后。
4. 邻近守卫全绿：既有六段常驻的断言**一字不动**仍绿（即钉住「没有改动既有口径」）。
5. 收口（**按用户要求，只到本地**）：commit（不 push）→ 工作树干净 → 仓外临时件清零。

## 五、未收口（如实留档）

- **不推送**（用户叫停）：README「## 门禁」节不换绑、CI 不读。
- **两条都不上扫描判据**：都要读整章上下文才判得准（§一百零五 既定取舍）。
- **效果无法在本仓度量**：「详略处置得当」「最后一拍有没有落下来」只能由作者真机生成一章后目检；
  本仓判据量不了，外部检测器读数不作结论依据。
- **P1 余项未动**：④ 结构上限改每千字（待真人语料分位）、⑦ 退化专项（电报体／短碎句专项，其判据同样要阈值，
  仍受 P0-① 的语料缺口牵制）。
