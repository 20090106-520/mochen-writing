# 明喻密度扫描判据（2026-10-20）：补上「生成端写死上限、扫描端无真身」的裂缝

## 一、这一刀要收的是什么

外部调研报告（`docs/research/2026-10-19-writing-craft-benchmark.html`）P2 价值序的
**⑨ 补修辞密度扫描判据**（对偶／排比／比喻）。报告的理由：中文上「修辞密度」有实测支撑
（AI 显著高于人类），比「破折号」这类**被证伪的表层特征**可靠。

本刀只取其中**比喻（明喻）**那一半，理由是它踩在本仓铁律上、且**不需要语料**：

- 生成端 `DE_AI_FLAVOR_STRUCTURE_INSTRUCTION` 第 ④ 条**已经写死数值上限**：
  「明喻（像/仿佛/好像/宛如）一章别超过三处」；
- 而扫描端（`packages/contracts/src/ai-flavor.ts`）**一条明喻判据都没有**——
  `analyzeAiFlavor` 只数：词表、认知转述、对偶、章末体、反差模板、情绪直陈、对话标签，
  明喻不在其中。

本仓铁律的反向一致性是：**生成端写死数值上限的判据，扫描端必须有同一份真身、并进退稿闸**
（§一百二十九 的前瞻note 原文：「将来若在生成端也给它们写死数值上限，再把名字移进来」——
④ 明喻正是这种情形，此前只是漏了）。所以本刀是**补一条真身**，不是新编一个阈值。

### 为什么不取「排比」和「破折号」

- **排比**：生成端第 ② 条只写「禁否定排比」，**没有数值上限**。要给它一个扫描起报线，
  就得凭空造一个数——那是**编数**，与 P0-①「不编数、等真人语料」的既定纪律冲突。
- **破折号**：生成端第 ① 条的上限写作「一章最多两三处」是**模糊表述**（不是一个写死的数），
  不构成「写死数值上限」；且报告明判它属**被证伪的表层特征**。两条理由都不成立，不动。

### 与既有判据的分工（不重复、不冲突）

- 明喻是**独立的句式判据**（按句式计，类别沿用 `essay`），与词表里那几条「描写套话」
  （「仿佛在诉说」「像是在诉说」这类固定短语）**不同层**：词表按词命中，明喻按标记密度命中。
  两者可能在同一段同时命中，各报各的（与「对偶／章末体／情绪直陈／对话标签」的既有关系一致）。
- 扫描端这一条与生成端 ④ **同吃一枚数字**：起报线 = 生成端上限 ＋ 1 = **4**；
  退稿闸判退线同样是 4（进闸清单，与对偶、对话标签一致）。上限 3 以内的合法额度**报都不报**。

## 二、纪律

1. **先红后绿**（TDD）：判据先写成红的，再动实现。
2. **明喻标记与生成端同源**：标记集合 = 生成端 ④ 点名的四枚（像／仿佛／好像／宛如），
   扫描端不另立一套。**宁可少报不误伤**——裸「像」用前后排除类挡掉成词干扰（图像·录像·影像·
   肖像·偶像·想像·好像·不像·像话·像样·像素·像片），两字标记「仿佛／好像／宛如」无歧义。
   刻意留的召回边界：`更像是` 这类比较句仍会命中（它本就是明喻构式），不额外放宽。
3. **既有判据一字不动**：对偶／章末体／反差模板／情绪直陈／对话标签的判据、阈值、既有用例全部保留。
4. **不改生成端提示词**：`prompt-assembly.ts` 第 ④ 条原文一字不动（本刀只补扫描真身）。
5. **用户叫停推送**：本刀只在本地提交，**不 push、不换绑 README 门禁、不读 CI**。
