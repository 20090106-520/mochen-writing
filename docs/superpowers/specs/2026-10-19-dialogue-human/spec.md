# 对话写法（三）：把「四稿拉满」的三条口径固化进仓（2026-10-19）

## 一、这一刀要收的是什么

来源是一次连续四稿的 A/B 实测：同一个故事《雾港的账》同一场戏，走**应用自身通路**
（CDP 连运行实例、`window.mochen.startTurn`，`agnes-3.0-flash`、`stageId draft`、
`thinkingLevel low`、联网关），逐稿改一版文案、再交外部检测器读一次。

| | 一稿 | 二稿 | 三稿 | 四稿 |
| --- | --- | --- | --- | --- |
| 正文字数 | 1110 | 1258 | 1278 | 1468 |
| 本仓词表命中/千字 | 0/0 | 0/0 | 0/0 | 0/0 |
| 句长均值 | 19.8 | 15.7 | 11.8 | 15.0 |
| 句长离散 | 0.64 | 0.78 | 0.71 | 0.90 |
| 退稿闸 | pass | pass | pass | pass |
| 外部检测器 · 人工特征 | 0% | 0% | 59.15% | **100%** |
| 外部检测器 · 疑似 AI | 75.86% | 100% | 40.85% | 0% |
| 外部检测器结论 | 未发现明显的人工创作特征 | 同上 | 人工创作特征较弱 | 人工创作特征显著 |

反复提交、页面独立核对，读数一致（外部检测器的读数只作**方向参照**，见 §二.4）。
四稿比三稿**多出来的**那三条改动，就是把人工创作特征从 59% 拉到 100% 的那三条——本节把它们固化进仓：

1. **对话标签「××说」几乎拆掉，靠动作切对话**——四稿 1468 字只剩 3 处；
   三稿 1278 字有 10+ 处。对话靠动作与场景进入（「她把茶杯推过去。『喝吧。』」），
   而不是「她说道：『喝吧。』」。
2. **对话里要有闲话与跑题**——跟剧情无关的内容（天气、吃的、谁家的事）先说两句、
   岔开、再绕回来；真人说话不句句奔正事。
3. **允许说错／说重后自己打断或改口**——四稿样本：
   「周把头，这印……是你贪的」→ 掐断 →「不是。我问一句……」。

另附一条：**段落长度彻底打散，不许每段都收在台词上**。

### 为什么这一刀是「固化」而不是「新发明」

上面三条已在四稿真机实测里验证过效果（唯一区别就是它们），但此前只写在**临时改的那一版文案**里
（连同上一次 `HUMAN_CRAFT_INSTRUCTION` 那段一起，见 `2026-10-18-human-traits/`），**没有一条落在仓里**——
换言之，把应用重开一次、用默认文案跑，模型看不到它们。本节是把它变成常驻口径。

### 三端落点（生成端说什么，扫描端就得能扫什么）

只有第 1 条可扫：贴着引号的「××说／说道」是可计数的固定句式。第 2、3 条与「段落打散」
都要读**整场对话的语义**才判得准（「这句是不是闲话」「这次改口是不是机械」正则判不出来），
按 §一百零五 既定取舍**只进生成端、不上扫描判据**。

## 二、纪律

1. **先红后绿**（TDD）：判据先写成红的，再动实现。
2. **生成端写明数值上限的判据才进退稿闸**（铁律）：第 1 条在生成端写明「一章最多三处」，
   扫描端起报线 = 上限＋1 = 4，并把该 label 移进 `AI_FLAVOR_STRUCTURE_GATED_LABELS`——
   这正是 §一百二十九 末尾留的那条前瞻（「将来要给别的句式写死数值上限，就把名字移进这张名单」）。
3. **不重复叮嘱**：既有四段常驻（`AI_FLAVOR_INSTRUCTION` / `DE_AI_FLAVOR_STRUCTURE_INSTRUCTION` /
   `QUALITY_INSTRUCTION` / `NARRATIVE_CRAFT_INSTRUCTION` / `HUMAN_CRAFT_INSTRUCTION`）**一字不动**。
   `QUALITY` 第 3 条已经点过「少用对话标签、用动作切」与「答非所问／潜台词」，但只一句带过；
   本段把它**落到可执行的数**（一章最多三处）并补三条它没说过的新口径（闲话跑题／说错改口／段落打散），
   分工写在常量注释里。
4. **外部检测器不作效果评估依据**（项目记忆）：它读数抖动、且不给逐句标注，
   效果只能由本仓判据 ＋ 作者目检闭环。
5. **用户叫停推送**：本刀只在本地提交，**不 push、不换绑 README 门禁、不读 CI**（§五 如实留档）。

## 三、改法（精确到文件与常量）

### 1) 生成端：`apps/desktop/src/main/prompt-assembly.ts`

新增常驻常量 `HUMAN_DIALOGUE_INSTRUCTION`（四条，照旧给**可执行判据**，不空喊「写得像人一点」）：

1. **少用「××说」标签**——对话靠动作和场景切（「她把茶杯推过去。『喝吧。』」比
   「她说道：『喝吧。』」像人写的）；贴引号的「××说／说道」**一章最多三处**（系统会数）；
   要用也带动作（「他盯着门口说」），别让「～说」单独占一行。
2. **对话里要有闲话与跑题**——真人说话不句句奔正事：先扯两句无关的（天气、吃的、谁家的事），
   说到一半岔开、再绕回来；一场对话里至少留一两句「没用但像人说的」话。
3. **允许说错、说重、改口**——想说的话不必一次说全：说重了可以自己截断
   （「这印……是你贪的」→「不是。我问一句——」），说错了可以停顿、改口、被自己咽回去；
   别让每个人开口就是一句滴水不漏的台词。
4. **段落长度打散，不许每段都收在台词上**——长段短段交替，有的段落停在动作、有的停在环境、
   有的停在一个没接完的物件上；段段都以对白收尾是本子在念，不是人在写。

落点：装配数组里**紧接 `HUMAN_CRAFT_INSTRUCTION` 之后**。

### 2) 扫描端：`packages/contracts/src/ai-flavor.ts`

- 新增 `AI_FLAVOR_DIALOGUE_TAG_PATTERN`：只认**两种贴身构式**，宁可少报不误伤——
  - 引号收尾后紧跟 ≤4 字的「说／说道」：`「……」他说。`；
  - 「说／说道」后紧跟冒号与引号：`他说：「……」`。
  刻意不收单独的 `说`（「说明／说话／虽说／听说」命中面太大），也不收半角直引号
  （`"他说过不会来。"` 里那个引号是**开**引号，会把引号内的转述误判成标签）。
- 新增 `AI_FLAVOR_DIALOGUE_TAG_LABEL`（显示名，按句式计，类别沿用 `essay`）。
- `AI_FLAVOR_STRUCTURE_MIN_COUNT[对话标签] = 4`（= 生成端上限 3 ＋ 1）。
- `AI_FLAVOR_STRUCTURE_GATED_LABELS` **追加**该 label。
- `analyzeAiFlavor` 与 `aiFlavorGate` 各补一条计数——**同一份正则，不抄第二份**。
- 文件头「四类口径」与 `AI_FLAVOR_STRUCTURE_MIN_COUNT` / `AI_FLAVOR_STRUCTURE_GATED_LABELS`
  的注释同步更正（进闸不再只有对偶一条）。

### 3) 退稿信：`apps/desktop/src/main/doc-tools-host.ts`

`verdict.structureOver` 非空时，信里那一句改成**按 label 现取上限**：
「句式超限：<label>（一章最多 N 处）——多出来的删掉，或换个写法把同一个意思说清楚。」
（N = `AI_FLAVOR_STRUCTURE_MIN_COUNT[label] − 1`，数字仍只住那一张表。）

为什么要改：原句写死了「一章最多一处」，只对对偶成立；清单里从此有两条、上限各不相同
（对偶 1、对话标签 3），措辞必须随 label 走，否则给模型的数是错的。

### 4) 巡检面板：`apps/desktop/src/renderer/src/utils/doc-checkup.ts`

「⑤ AI 味扫描」直接吃 `analyzeAiFlavor`（单一真身），新 label 自动进报告——**零改动**，
与退稿闸同一份判据（项目铁律）。

### 5) 不改动的既有判定（回读确认）

- 生成端既有五段常驻常量与装配顺序的前五段位置：**一字不动**。
- `AI_FLAVOR_TERMS`、认知转述／对偶／章末体／反差模板／情绪直陈五条正则、
  `sentenceStartRepeat` / `sentenceRhythmOf` / `textSimilarity`、`AI_FLAVOR_GATE` 四阈值、
  `AI_FLAVOR_REPEAT`：**一字不动**。
- 退稿闸既有的四条老理由（词密度／句首复读／句长过匀／对偶超限）、复读条、
  防死循环（原样重交放行）、「换汤不换药」点破、连续退稿升级：**一字不动**——本刀只加了一条独立理由。

## 四、验收（AC）

1. 先红：新判据跑出失败（提示词缺新段、对话标签未被计数、未进闸）。
2. 后绿：`corepack pnpm verify` 全绿（prettier → 6 枚 tsc → eslint → 边界 → 行数预算 → vitest → `VERIFY_EXIT=0`）。
3. 提示词到位：跑 `defaultPromptFor` 读回，新段在 `HUMAN_CRAFT_INSTRUCTION` 之后。
4. 邻近守卫全绿：`doc-tools-host.test.ts` 对话标签超限一条 ＋ 既有各组（含干净稿仍放行）。
5. 收口（**按用户要求，只到本地**）：commit（不 push）→ 工作树干净 → 仓外临时件清零。

## 五、未收口（如实留档）

- **不推送**（用户叫停）：README「## 门禁」节**不换绑**、CI **不读**——因此本刀没有 CI 读数，
  README 里那两格仍指向上一次真读过的提交，这是**有意为之**，不是漏收。
- **第 2／3 条与「段落打散」不设扫描判据**：要读整场对话的语义才判得准（§一百零五 既定取舍）。
- **对话标签的召回边界**（有意为之，本刀不放宽）：只认贴着引号的 `说／说道`；
  `问／答／道`「××问」这类标签、以及不带引号的 `他说，……` 都**不抓**——
  放宽会把常态合法构句（`他这么一说，`）一并咬进来，收益不抵票据。
- **上限 3 是绝对数、不随章长伸缩**：与既有结构上限（对偶「一章最多一处」、明喻「一章别超过三处」）
  同一口径（都是绝对数）。若真机发现长章被误伤，再按「每千字」重估。
- **效果无法在本仓度量**：「更像人写的」只能由作者真机生成一章后目检；
  平台过审率本仓量不了；外部检测器读数不作结论依据。
