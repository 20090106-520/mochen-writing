# 皮肤素材规格单（整窗画面 + 挂件）

批次 5-㊷ · 2026-10-08

这张单子的用途有两个：一是墨宸自己按它出图，二是**把出图交给别人做时，直接整张贴过去**——
用户说过「我自己提供图，给我什么样的，我让他给你做就行了」。
所以每一条都写成可交付的硬指标，不写「好看一点」这种没法验收的话。

---

## 一、整窗画面（`art` 层）

### 1. 规格

| 项 | 要求 | 为什么 |
| --- | --- | --- |
| 尺寸 | **1536×1024（3:2）**，最小不低于 1440×960 | 桌面端整窗要能铺满 1920 宽；比例不对就会被 `background-size: cover` 裁掉两侧，立绘常常正好被裁没 |
| 格式 | JPG（质量 ≥ 82）或 PNG，单张 **≤ 900KB** | 这张图每次开窗都要读，太胖直接拖慢首屏 |
| 落盘 | `apps/desktop/src/renderer/public/skins/<id>.jpg` | 渲染层根（`/skins/...`）是唯一被允许的出处；CSS 里的路径由 `appearanceSkinVisual.ts` 的 `ART_FILES` 给，**数据表里不许出现路径** |
| id | 短横线小写，与皮肤表、contracts 枚举、中文档名表**三处同名** | 铁律 6：一份真相不许有两个名字 |

### 2. 构图硬规则（这几条决定「能不能用」，不是审美偏好）

> **2026-10-17 第三刀就地更正**：本节五条是为**场景画**（有人工构图可调）写的，
> 对**人像摄影**这个范畴**大部分不适用**——照片的构图改不了（不裁切、不重绘是本仓既定的取材纪律），
> 第 1 条那句「中间一整片必须是低信息量的暗区」对人像**当场就是错的**：肖像主体本来就在中间。
> 现况是：这五条对八张 Unsplash 人像**一条都没有逐条校验过**，
> 像素闸也据此改了射程（`check-scene-art.mjs` 只剩 `G1` 分层 + `G2` 全局不空，
> 原 `G2` 缘中差与 `G3` 静动比降为观察项，理由写在脚本头部）。
> **下面这五条仍是「下一批自绘 / 委托场景画」的验收标准**，原样保留、逐字不动。
> 与本节口气最冲的那句「否则立绘会被面板压掉，画了等于没画」照旧成立——那是真机量出来的。
>
> **2026-10-17 第四刀就地更正**：上面那句「八张 Unsplash 人像」**已被用户否掉**——
> 「**我要的是中国的真人美女图片或动漫二次元图片做装扮不要外国的**」。八张于是改成
> **四张 Pixiv 原创动漫插画 × 昼夜两版**。对中国真人照片，本机**没有可用通路**（两站的
> CDN 通、搜索页与 API 全被拦）；动漫这条线里也**只取 `original` 标签**（非游戏 / 番剧角色）。
> ⇒ 本节五条对**动漫插画**同样**一条都没有逐条校验过**，「只算部分过完」的结论不变。

1. **中间一整片必须是低信息量的暗区。**
   墨宸是三栏（导航 / 对话 / 右栏），中间那条正是正文与对话落的地方。
   画里的主角、立绘、灯、窗光，**一律放到左右两缘或上下两条带里**，
   中间留给「同一材质但压暗、没有细节」的区域。
   ⇒ 生图时这条要直接写进 prompt，否则立绘会被面板压掉，画了等于没画。
2. **左右两缘允许有主体**（它们会分别落在导航栏与右栏背后），
   但**上下各 12% 不许放关键元素**——窗口顶栏、输入区浮层会盖在那里。
3. **整体压深，且明暗是渐变不是硬边。** 运行时还会在上面叠一层纱（`--skin-art-veil`），
   画本身已经压到「亮部不过 60% 灰」时，正文的可读性才由计算说了算：
   正文色对最终底色 **≥ 7:1**（WCAG AAA），这条由 `appearance-theme-readability.test.ts` 钉着，
   画得过亮会在守卫这一层红。
4. **浅色版与深色版必须是同一套构图**（「昼」与「夜」）。
   墨宸每套皮肤都要配深浅两版——`mode` 可以是「跟随系统」，
   只出一版等于有一半时间在用不相配的那一版。
   昼版不是「把亮度拉高」：光源方向、色温、被照到的物件要跟着换，暗区位置不许动。
5. **不许有可读文字、logo、水印**，也不许画出「界面」（面板、按钮、光标）。
   画里放假界面会和真界面重影。

### 3. 风格基调（墨宸 = 深渊 × 写作）

- 手绘插画 / 概念画方向，**厚涂或水彩质感都可以，像素风不要**（用户明确否过）。
- 母题是「**深海 / 深渊里一间和稿子有关的地方**」：藏书阁、书舟、灯塔书房、墨潭书亭……
- 道具必须是**稿子那一类**（卷轴、稿纸、羽毛笔、墨水瓶、灯、书册），
  不是代码、不是终端、不是键盘。这条是「按写作软件设计」与「按别的工具软件设计」的分界。
- 人物（如果有）：蓝发、鲸耳的「汐」是既有角色，新场景沿用同一角色设定才连得上。

## 二、挂件（`ornament` 层，5-㊷ 之后接）

用户那句「加入能有画的**和挂件」」里的第二件。它和 `art` 是两层不同的东西：
`art` 铺满整窗，`ornament` 是**一角的小件**（挂在角落、不改变整窗明暗）。

| 项 | 要求 |
| --- | --- |
| 尺寸 | **512×512**，**必须是带透明通道的 PNG**（`public/skins/ornaments/<id>.png`） |
| 内容 | 单一小物，居中，四周留 ≥ 8% 空白，不要投影到画布外（挂位由 CSS 决定，不由素材决定） |
| 挂位 | 初定两枚：**右下**（不压输入区）与**侧栏底部**（不压导航文字）；一枚皮肤最多两处 |
| 亮度 | 挂件自身不要过亮：它压在真界面旁边，运行时还会再叠一层 `opacity`，过亮会抢正文 |
| 尺寸档 | 同一枚要能在 96px / 140px 两档下都不糊 ⇒ 按 512 出，别按 128 出 |

候选四枚（都属「稿子」母题，与场景图同调）：

1. `whale-tassel` —— 鲸尾形书坠，坠着一枚小卷轴；
2. `ink-bottle` —— 墨水瓶，瓶口斜插一支羽毛笔；
3. `deep-lamp` —— 深海里的一盏小提灯（给暗区一点暖光）；
4. `coral-page` —— 一小枝珊瑚压着的稿纸角。

> 为什么现在还没接进代码：挂件层的契约（`APPEARANCE_ORNAMENTS`）一旦加进枚举，
> 就会在筛选条上出现一个**没有任何皮肤在用的档**——那正是 5-㊷ 刚修掉的「死档」缺陷。
> ⇒ 枚举、运行时 token、CSS 挂位、皮肤表条目、素材，**同一批一起进**。

> **2026-10-17 第五刀就地更正（本节现况）**：
> ① 上面那张表里的**尺寸 / 编码**两条**已被推翻**——挂件最终没走 `512×512 透明 PNG`，
>    走的是**开源 emoji 项目 Twemoji 的矢量 SVG**（`public/skins/ornaments/<id>.svg`，
>    `viewBox 0 0 36 36`）。推翻的理由是用户当天改裁定：「你都可以直接从网上搜索导入……
>    开源项目也行，**不用自己创建**」——PNG 那一路要自己画，SVG 那一路是导入现成开源素材。
>    原文保留，它记的是 5-㊷ 当时设想的做法。
> ② 上面那「四枚候选」（`whale-tassel` / `ink-bottle` / `deep-lamp` / `coral-page`）
>    **一枚都没被采用**：实际落地的是 **16 枚 Twemoji**，档名与码位见
>    `docs/ATTRIBUTION.md` 的「皮肤窗角挂件」一节（本仓**不自绘**任何一枚，也没有自绘管线）。
> ③ 上面那句「为什么现在还没接进代码」**已不成立**：枚举、运行时 token、CSS 挂位、
>    皮肤表条目、素材这一次**同一批一起进**了，筛选条上**没有**出现死档
>    （`appearance-skin-assets.test.ts` 逐枚钉「每个档名都有中文名且无死档」）。
> ④ 「挂位」那一行也收窄了：实际只落**右下角**一处（`right 28px bottom 28px`，
>    `--skin-ornament-size: min(18vmin, 184px)`），「侧栏底部」那一处没有做。

> （常量名 `OWN_ART_*` → `PHOTO_ART_*`）。原文保留——它记的是波2 那一批当时的口径。
> 新口径与它冲突的两条已在下文逐条更正：
> ① Unsplash License 免费用于商业与非商业用途、**可修改、可再分发**，所以上面第二条那句
> 「委托他人绘制时须拿到『可商用、可修改、可再分发』的书面授权」**对 Unsplash 这条通路不作要求**

> ② 但许可**只管照片的著作权，不含模特肖像权**——这层风险已如实写进 `docs/ATTRIBUTION.md`，
> 由分发方自行评估，本仓不声称已取得模特授权。

> **2026-10-17 第四刀就地更正**：用户把 Unsplash 那批整个否掉（「**不要外国的**」），

> ① 这四张**没有拿到任何再分发授权**（画师发在 Pixiv 的原创作品，Pixiv 条款不授予第三方
>    再分发权），所以皮肤表上那两句改成 `ANIME_ART_ORIGIN`＝「动漫插画（Pixiv 原作）」/
>    `ANIME_ART_LICENSE`＝「**未获再分发授权**」——**不是「可商用」那一类**，如实写。
> ② 「模特肖像权」那一层随人像一起消失（画里不是真人），**新的一层是「再分发权」**，
>    同样如实写在 `docs/ATTRIBUTION.md`，由分发方自行评估。
> ③ 本节最后那条「明确不进表」的结论**不受影响**：那两条上游仓库仍是 CC BY-NC-SA，仍不进。

> （`ANIME_ART_LICENSE` 一字不改）；「再分发权」这一层仍旧如实写在 `docs/ATTRIBUTION.md`。

> **性质不同**——它**允许再分发**，但**要求署名**（署名清单在 `docs/ATTRIBUTION.md` 那节）。

- 自绘/委托的图：**`origin` 写「墨宸原创画面」、`license` 写「本仓自有」**。
  与改装自 MIT 上游的那几条要能一眼分开，所以这是两句不同的话，不是复用同一句
