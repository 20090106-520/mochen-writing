# 皮肤素材规格单（整窗画面 + 挂件）

批次 5-㊷ · 2026-10-08

这张单子的用途有两个：一是墨宸自己按它出图，二是**把出图交给别人做时，直接整张贴过去**——
用户说过「我自己提供图，给我什么样的，我让他给你做就行了」。
所以每一条都写成可交付的硬指标，不写「好看一点」这种没法验收的话。

---

## 一、整窗画面（`art` 层）

### 1. 规格

| 项 | 要求 | 为什么 |
| --- | --- | --- |
| 尺寸 | **1536×1024（3:2）**，最小不低于 1440×960 | 桌面端整窗要能铺满 1920 宽；比例不对就会被 `background-size: cover` 裁掉两侧，立绘常常正好被裁没 |
| 格式 | JPG（质量 ≥ 82）或 PNG，单张 **≤ 900KB** | 这张图每次开窗都要读，太胖直接拖慢首屏 |
| 落盘 | `apps/desktop/src/renderer/public/skins/<id>.jpg` | 渲染层根（`/skins/...`）是唯一被允许的出处；CSS 里的路径由 `appearanceSkinVisual.ts` 的 `ART_FILES` 给，**数据表里不许出现路径** |
| id | 短横线小写，与皮肤表、contracts 枚举、中文档名表**三处同名** | 铁律 6：一份真相不许有两个名字 |

### 2. 构图硬规则（这几条决定「能不能用」，不是审美偏好）

1. **中间一整片必须是低信息量的暗区。**
   墨宸是三栏（导航 / 对话 / 右栏），中间那条正是正文与对话落的地方。
   画里的主角、立绘、灯、窗光，**一律放到左右两缘或上下两条带里**，
   中间留给「同一材质但压暗、没有细节」的区域。
   ⇒ 生图时这条要直接写进 prompt，否则立绘会被面板压掉，画了等于没画。
2. **左右两缘允许有主体**（它们会分别落在导航栏与右栏背后），
   但**上下各 12% 不许放关键元素**——窗口顶栏、输入区浮层会盖在那里。
3. **整体压深，且明暗是渐变不是硬边。** 运行时还会在上面叠一层纱（`--skin-art-veil`），
   画本身已经压到「亮部不过 60% 灰」时，正文的可读性才由计算说了算：
   正文色对最终底色 **≥ 7:1**（WCAG AAA），这条由 `appearance-theme-readability.test.ts` 钉着，
   画得过亮会在守卫这一层红。
4. **浅色版与深色版必须是同一套构图**（「昼」与「夜」）。
   墨宸每套皮肤都要配深浅两版——`mode` 可以是「跟随系统」，
   只出一版等于有一半时间在用不相配的那一版。
   昼版不是「把亮度拉高」：光源方向、色温、被照到的物件要跟着换，暗区位置不许动。
5. **不许有可读文字、logo、水印**，也不许画出「界面」（面板、按钮、光标）。
   画里放假界面会和真界面重影。

### 3. 风格基调（墨宸 = 深渊 × 写作）

- 手绘插画 / 概念画方向，**厚涂或水彩质感都可以，像素风不要**（用户明确否过）。
- 母题是「**深海 / 深渊里一间和稿子有关的地方**」：藏书阁、书舟、灯塔书房、墨潭书亭……
- 道具必须是**稿子那一类**（卷轴、稿纸、羽毛笔、墨水瓶、灯、书册），
  不是代码、不是终端、不是键盘。这条是「按写作软件设计」与「按别的工具软件设计」的分界。
- 人物（如果有）：蓝发、鲸耳的「汐」是既有角色，新场景沿用同一角色设定才连得上。

## 二、挂件（`ornament` 层，5-㊷ 之后接）

用户那句「加入能有画的**和挂件」」里的第二件。它和 `art` 是两层不同的东西：
`art` 铺满整窗，`ornament` 是**一角的小件**（挂在角落、不改变整窗明暗）。

| 项 | 要求 |
| --- | --- |
| 尺寸 | **512×512**，**必须是带透明通道的 PNG**（`public/skins/ornaments/<id>.png`） |
| 内容 | 单一小物，居中，四周留 ≥ 8% 空白，不要投影到画布外（挂位由 CSS 决定，不由素材决定） |
| 挂位 | 初定两枚：**右下**（不压输入区）与**侧栏底部**（不压导航文字）；一枚皮肤最多两处 |
| 亮度 | 挂件自身不要过亮：它压在真界面旁边，运行时还会再叠一层 `opacity`，过亮会抢正文 |
| 尺寸档 | 同一枚要能在 96px / 140px 两档下都不糊 ⇒ 按 512 出，别按 128 出 |

候选四枚（都属「稿子」母题，与场景图同调）：

1. `whale-tassel` —— 鲸尾形书坠，坠着一枚小卷轴；
2. `ink-bottle` —— 墨水瓶，瓶口斜插一支羽毛笔；
3. `deep-lamp` —— 深海里的一盏小提灯（给暗区一点暖光）；
4. `coral-page` —— 一小枝珊瑚压着的稿纸角。

> 为什么现在还没接进代码：挂件层的契约（`APPEARANCE_ORNAMENTS`）一旦加进枚举，
> 就会在筛选条上出现一个**没有任何皮肤在用的档**——那正是 5-㊷ 刚修掉的「死档」缺陷。
> ⇒ 枚举、运行时 token、CSS 挂位、皮肤表条目、素材，**同一批一起进**。

## 三、许可与出处（这一节不许跳过）

- 自绘/委托的图：**`origin` 写「墨宸原创画面」、`license` 写「本仓自有」**。
  与改装自 MIT 上游的那几条要能一眼分开，所以这是两句不同的话，不是复用同一句
  （`themePresets` 的投影判据靠这个区分，混用会把带画的皮投影进「主题配色」那张表）。
- **委托他人绘制时必须拿到「可商用、可修改、可再分发」的书面授权**，
  并把授权写进 `docs/ATTRIBUTION.md`。
- 明确不进表的：`Small-tailqwq/dsh-deep-whale`（美术部分 CC BY-NC-SA 4.0，禁商用）、
  `GGBond2424648901/deep-whale-day-night-theme`（整仓 CC BY-NC-SA）。
  用户 2026-10-08 选的素材来源是「自绘 + 自有图」，所以这两条继续按「不进」处理，
  理由是**许可与来源已经定了走自绘**，不是「因为要卖钱」。

## 四、验收清单（新素材进表前逐条过）

1. [ ] 中间暗区实测：把正文区的透明度放行到 52% 时，正文对底色仍 ≥ 7:1（跑可读性守卫）。
2. [ ] 昼夜两版构图逐元素对得上（暗区位置、主体左右关系）。
3. [ ] 单张 ≤ 900KB，尺寸与比例符合第一节。
4. [ ] 三处同名：`APPEARANCE_ARTS` / 皮肤表 / `APPEARANCE_ART_LABELS`。
5. [ ] `ART_FILES` 里有对应文件且文件真实存在（守卫会读盘，缺文件当场红）。
6. [ ] 皮肤广场卡片预览与真机整窗**都看过**（窄窗 1120 与 1920 各一次）。
7. [ ] `docs/ATTRIBUTION.md` 记了来源与许可。
8. [ ] **像素级三道闸过**（波2a 加的，矢量位图都适用）：把成品画成 320×180 后量
   `G1` 分层桶数 ≥4、`G2` 两缘亮度跨度 ≥18 且与中段均值差 ≥10、`G3` 中段水平边缘能量 ≤4
   且两缘至少 2 倍——跑 `node apps/desktop/scripts/check-scene-art.mjs`（需先 build 并自起
   一台带 `--remote-debugging-port=9234` 的实例，见脚本头部那三步），
   它末尾那条「空渐变必须判红」的反向用例同时必须**红**。
9. [ ] 目检用 **png 不用 jpeg**：暗部 banding 会被 q80 自己压出来，看错一次就要重跑一轮；
   脚本每轮给素材 URL 换新串号，否则读到的是 HTTP 缓存里的上一版。
