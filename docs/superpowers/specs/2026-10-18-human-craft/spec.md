# 人味写作：补叙事手法常驻段 ＋ 扫描端对齐（2026-10-18）

## 一、这一刀要收的是什么

用户逐字指令：

> 「继续优化，我这个软件写作小说质量不行，AI味道太大，文笔太潦草，跳跃太大了，没有心理描写，
> 动作描写，以环境弄表示心情，还有其他写作手法和真人。审核通过率太低，人机味太重，无法审核，
> 无法上架，小说被判DA。小说减少AI味道，让它变得更像真人写作。解决这个问题」

拆成五点病灶：① AI 味太重；② 文笔潦草（一笔带过、没有可感的节拍）；③ 跳跃太大（场景硬切、没有过渡）；
④ 缺**心理描写／动作描写／以环境映心情**这三样手法；⑤ 人机味导致过不了平台审核。

**既有体系已覆盖的**（不在本刀范围）：

- 词与句的去味 —— `AI_FLAVOR_INSTRUCTION`（`apps/desktop/src/main/prompt-assembly.ts`），词表与体检同源；
- 结构级去味九条 —— `DE_AI_FLAVOR_STRUCTURE_INSTRUCTION`（同文件），破折号／否定排比／章末四禁等；
- 细腻度五条 —— `QUALITY_INSTRUCTION`（同文件），五感、具体名词、对话节拍、角色声音、续写无缝；
- 扫描端 —— `packages/contracts/src/ai-flavor.ts` 的词库 + 认知转述/结构级三类正则，体检与退稿闸同吃一份。

**空缺的（正是用户点名的那五样）**：

| 病灶 | 生成端 | 扫描端 |
| --- | --- | --- |
| 心理描写（怎么演情绪） | 只在 AI_FLAVOR_INSTRUCTION 里带过一句「心理活动用动作、对话和细节演出来」 | 只有认知转述句式，无「给情绪命名」的判据 |
| 动作描写（怎么拆节拍） | **一字未提** | 无 |
| 以环境映心情（写具体的物） | 只在 QUALITY 第 1 条要求「非视觉感官」 | 无环境套话判据 |
| 场景过渡（换场锚） | **一字未提** | 无（要读整章，不上正则） |
| 节奏（快慢分） | 只有句子层面的「长短句错落」 | 只有句长波动/起手复读两枚节奏闸 |

## 二、纪律（为什么不只堆提示词）

1. **生成端说什么，扫描端就得能扫什么**（项目铁律／§一百零五 的教训）。上一批 `DE_AI_FLAVOR_STRUCTURE_INSTRUCTION`
   写了九条结构约束，扫描端当时只补了「认知转述隔副词」一处，两端对不齐——本刀不许重演：
   **每写一条能机器判的生成端约束，同批补一条扫描端判据**。
2. **同一件事不留第二份实现**（铁律 6）。新词一律进 `AI_FLAVOR_TERMS`，提示词点名单由 `aiFlavorPromptList()`
   现拼，**不许在提示词里手抄一份**。
3. **不能机器判的不硬上正则**（§一百零五 既定取舍）。场景过渡、明喻密度、动作是否拆了节拍——
   要读整章上下文才判得准，**只进生成端，扫描端不设判据**，理由写进本节。
4. **SSoT 与判据先红后绿**（TDD）。
5. **外部检测器不作为效果评估依据**（项目记忆）：朱雀等读数抖动，效果以「本仓判据全绿 + 真机目检」为准。

## 三、改法（精确到文件与常量）

### 1) 生成端：`apps/desktop/src/main/prompt-assembly.ts`

新增常驻常量 `NARRATIVE_CRAFT_INSTRUCTION`（五条，与 QUALITY 的「给可执行判据、不空喊细腻一点」同一口径）：

1. **心理靠演不靠说** —— 禁给情绪命名（「他感到愤怒」），改写身体反应／手上动作／视线落点／注意到的物件。
2. **动作拆节拍** —— 关键动作拆成 2–4 个能拍下来的具体动作，按先后写；概括是叙述，节拍才是画面。
3. **环境映心情** —— 只写**这个人物此刻会注意到的**具体物；点名禁「夜色深沉」「寒风刺骨」这类空泛套话。
4. **换场要有过渡锚** —— 时间推进／地点转移／一个收尾动作；一场不留坑、下一场不凭空出现。
5. **快慢要分** —— 冲突处放慢（一个瞬间拆成几句），交代过场处收紧。

落点：`defaultPromptFor` 的装配数组里，**紧接 `QUALITY_INSTRUCTION` 之后**（去味三段 → 细腻度 → 叙事手法 → 动态段）。

### 2) 扫描端：`packages/contracts/src/ai-flavor.ts`

- **新增 15 条 `cliche` 词**（分两组，各带注释）：
  - 概括情绪：`百感交集`、`五味杂陈`、`心情复杂`、`心潮澎湃`、`思绪万千`、`感慨万千`、`心如刀割`、`热泪盈眶`；
  - 空泛环境套话：`夜色深沉`、`夜色如墨`、`寒风刺骨`、`寒风凛冽`、`灯火阑珊`、`月光如水`、`万籁俱寂`。
  （cliche 阈值 2，照旧不设专项阈值。）
- **新增 1 条句式正则** `AI_FLAVOR_EMOTION_PATTERN` ＋ `AI_FLAVOR_EMOTION_LABEL`
  「情绪直陈（感到／涌起＋情绪词）」：认「感到／觉出／生出／涌起／泛起／涌上／掠过／充满
  ＋[程度·量词]＋情绪词」这一**构式**，只对构式报，不是见到情绪词就报。
  类别沿用 `essay`（替读者下结论的同一族），阈值走 `AI_FLAVOR_STRUCTURE_MIN_COUNT` 给 **3**（同认知转述：反复用才是机器味）。
- `analyzeAiFlavor` 与 `aiFlavorGate` 各加一处 `line.match` / `text.match`（与既有三条结构级正则同一批），
  **闸不计阈值、全量计入**，`hits` 口径扩为「描写套话＋议论腔＋认知转述＋结构级三类＋情绪直陈」。
- 同步更正文件头「四类口径」与 `AI_FLAVOR_GATE` 的注释，把新条写进去。

### 3) 判据（先写失败，后实现）

  断言五样手法语在常驻提示词里（含点名禁「夜色深沉」）。
- `packages/contracts/test/ai-flavor.test.ts`：追加 **1 条**词表断言（新词进表且进提示词点名单）
  ＋ **1 个 describe**（情绪直陈：3 次起报／多种构式／反例不误伤／退稿闸同批认）。

## 四、不改动的既有判定（回读确认）

- `AI_FLAVOR_TERMS` 的四类枚举不变（`adverb/cliche/essay/cognitive`）——情绪直陈是句式，**不占词表项**，
  `AI_FLAVOR_CATEGORY_LABELS` 不新增键（`test 词库` 那条 `toEqual(["adverb","cliche","essay"])` 仍绿）。
- 既有三条结构级正则、认知转述正则、`sentenceStartRepeat`、`sentenceRhythmOf`、`textSimilarity`：**一字不动**。
- 退稿闸阈值 `AI_FLAVOR_GATE`：**不动**（只扩口径，不放宽也不收紧）。
- 既有退稿闸用例的样稿（`HEAVY`、`mild`、`adverbsOnly`）不含新词与新构式，读数不变。
- `apps/desktop/src/renderer/src/utils/doc-checkup.ts` 只 `export { analyzeAiFlavor }`，新条目自动流向体检表；
  `SideNavTermsReport.vue` 按 category 取 label，句式条目的 `term` 直接显示，无需改。

## 五、验收（AC）

1. 先红：新判据跑出失败（提示词缺段 / 词表缺词 / 正则缺条）。
2. 后绿：`corepack pnpm verify` 全绿（prettier → 6 枚 tsc → eslint → 边界 → 行数预算 → vitest → `VERIFY_EXIT=0`）。
3. 提示词到位：跑 `defaultPromptFor` 读回，新段在 `QUALITY_INSTRUCTION` 之后。
4. 真机/单测：体检与退稿闸对新判据确有反应（正则用例 + 闸用例）。
5. 收口：commit + push（`feat/plan3-interaction-and-assembly`）→ 读真实 CI → README「## 门禁」节换绑
   → 台账 `docs/superpowers/plans/2026-10-09-full-scan-report.md` 补记 → 清理仓外临时件。

## 六、未收口（如实留档）

- **场景过渡**、**动作是否拆了节拍**、**明喻密度**、**否定排比/破折号甩结论**：要读整章上下文才判得准，
  按 §一百零五 既定取舍**不上正则**，只进生成端常驻约束，归体检人工判读。
- 平台审核（番茄/起点等）的过审率**本仓无法度量**：本刀治的是生成端手法与自检口径，
  「更像真人」的效果只能由作者目检，**不以任何外部检测器读数作结论**（项目记忆）。
- `agent-profile.ts` 的 `lead-writer` 档案提示词仍是一句「按大纲起稿本章正文」——
  本刀靠**常驻段**覆盖全部档案，不动单个档案（避免牵动六枚档案的既有判据）。
