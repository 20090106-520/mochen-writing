## 一、第三级文字：先让它能被守住，再改那个数

起点是一条真机红字：`--text-tertiary` 浅档实测 **2.87:1**（AA 正文要 4.5）。
这个数早就量到过，但只写在注释里——因为系数当时写在 `setProperty` 那一行里，
守卫拿不到同一个数，拦不住任何人把它改回去。「知道但没拦」就是这么来的。

改法分两步，顺序不能反：

1. 把浅/深两份原值搬成常量 `TERTIARY_TEXT_MIX`（`appearanceThemeRuntime.ts:251`），
   调用点改成读它（同文件 `:370-373`）；
2. 守卫按**应用自己这一份**算（`appearance-skins.test.ts` 新增那条
   「第三级文字对页底与卡面 ≥ 4.5:1」），于是**这条第一次跑就是红的**，
   红在真实缺陷上（汐·昼阁浅版对页底 2.87、对卡面 2.74），而不是红在 import 不到东西。

系数怎么定的（八套皮肤 × 深浅 × 页底/卡面的完整阶梯，都在守卫的推导注释里）：

- 浅档 0.48–0.72 逐档算过：要到 4.5 至少 0.69，而次要文字就是 0.71 ⇒ **浅色的"第三级"买不到层级**。
  这不是数值巧合，是「拿底色混前景色当第三级」这个机制的上限：浅底上任何更浅的灰都贴回底色。
  ⇒ 处置：**浅档与次要同级（0.71），第三级在浅色靠字号与位置区分，不假造一档色**。
- 深档 0.62 就能全员 ≥ 页 5.97 / 卡 4.94，而次要是 0.72 ⇒ 深色那一档可见的浅**留得住**，保留。

影响面如实报：`var(--text-tertiary)` 87 处 + 别名 `var(--text-dim)` 43 处 = **130 处消费点**，
分布在 14 个样式/组件文件（卡脚元信息、时间戳、字数统计、面板副标题那一类小字）。
浅色皮肤下这 130 处一起变深一档——这是有意的，它们本来就虚到读不清。

## 二、广场卡面跨皮肤漏底：守卫算的底 ≠ 屏幕上画的底

真机 6×6 无损 PNG 采样量到浅色模式下四套夜皮的卡片：**卡说明 2.11:1、卡脚出处 2.08:1**。
静态守卫全绿。两边不矛盾——守卫算的是「当前这一套的卡面」，屏幕上画的却是
「**候选那一套**的卡面」，根本不是一张底。

病因在 `SkinGalleryPage.vue`：`previewStyle(skin)` 把候选皮肤的五层 token（含
`--skin-glass-card-fill`）挂在 `<li class="skin-card">` 上，而 `.skin-card` 的背景正是那枚
token（`theme-runtime.css:354` 那条 `:where(.extension-card, .skin-card, …)` 玻璃规则）。
于是候选那套的卡面铺在了**装着页面字色的那一片**上——字跟着页面走、底跟着候选走。

改法：token 只留给预览块（那才是「换上之后长这样」的那一层），卡片本体跟着当前生效的那套。

```html
<li v-for="skin in skins" :key="skin.id" class="skin-card">
  <div class="skin-card-preview" :style="{ ...previewStyle(skin), ...previewTone(skin) }">
```

守卫 `appearance-skin-plaza-wiring.test.ts` 新增一条同名的：正向钉 token 落在预览块上，
**反向**钉 `<li class="skin-card">` 上不许再出现 `previewStyle`——只有反向断言才有牙齿
（token 回到 `<li>` 时，预览块自己那份还在，旧的两条照样绿）。
顺带钉住并排对比那一栏：`.skin-compare-item` 若不开始铺底，它带 `previewStyle` 是安全的。

两个方向都做过变异验红（漏底复原 → 反向断言红；预览块那份删掉 → 正向断言红），改回后全绿。

## 三、生成器与像素闸进仓：结果之外还要有来源

原先六张 SVG 的来源（生成器 + 像素复核）住在 `.superpowers/sdd/`，整目录 git-ignored
⇒ 远端只有**结果**，没有**来源**：改一张画的人只能重画，判合格的人找不到那道门。

搬进 `apps/desktop/scripts/`：

| 文件 | 角色 |
| --- | --- |
| `gen-scene-svgs.mjs` | 六道调色板闸 + 出图；输出目录按本脚本位置（`import.meta.url`）解析 |
| `check-scene-art.mjs` | G1/G2/G3 像素级复核 + 空渐变反向用例；自带最小 CDP 夹持（只暴露 `evaluate`，`CDP_PORT` 默认 9234），不再依赖仓库里不存在的那份 `tmp-cdp.mjs` |

搬运时验过两件必须成立的事：

1. **逐字节可复现**——从仓库根、从 `apps/desktop` 各跑一次，六张 SVG 的 sha256 与已提交版本
   全部 `OK`，且没有造出 `apps/desktop/apps/desktop/…` 那棵假树（原先 cwd 相对写法就会）；
2. **闸在新家真的在响**——`node apps/desktop/scripts/check-scene-art.mjs` 对着我自起的
   9234 实例跑完：六张全过 + 末尾反向用例判红，退出码 0。

顺手做的两件收口：`apps/desktop/package.json` 加 `gen:scene-svgs` / `check:scene-art` 两条
script（**零新增依赖**）；仓内三处指向旧临时脚本名的注释/文档全部改到新路径
（`appearanceSkins.ts:247,252`、波2a 台账、素材规格单 §4 第 8 条）。
生成器从 `.cjs` 改成 `.mjs`：仓里 eslint 那条 `no-require-imports` 对它一视同仁，
与其加例外不如用与闸同一款的 ESM 写法。

目检类一次性探针（`tmp-look-art.mjs`、`tmp-find-seam.mjs`、`tmp-verify-wave2a.mjs`）
**不搬**：它们绑的是当轮 CDP 会话与临时截图目录，搬进去只会变成第二套没人能跑的契约。

rgb(88,118,122) 上第三级只有 1.86、卡面 3.92–4.42」。这次复跑对上后原因是**仪器错**：

## 五、仍未收口的那一处：浅色档有两张卡次要文字 4.34–4.38

`书舟 · 夜航 / 卡说明 4.38`、筛完四张时 `墨潭 · 沉雾 / 卡说明 4.34`（同一处第三级 4.42）。
底不是页底那枚色值，是复色：`bg rgb(209,229,234)` 对同档别处的 `rgb(221,239,244)` ——
**画层透过 52% 的页底放行 + 40% 卡面玻璃，把那一小块垫底压暗了**。
系数这条路在浅色已经走到头（第三级与次要同值，再往深就是"小字比正文还重"）。

三个选项，要用户拍，我没有擅自选：

- **A｜放行名单收窄**：文字落的那一带不许画层透出（把 `.skin-gallery` 那片的
  `color-mix(… 52% …)` 降到 ~40%）。代价：广场看到的画变淡，与「有画才进广场」的初衷顶一下。
- **B｜卡面自带一层底**：`.skin-card` 的文字区加一层不透明衬垫（`--skin-glass-card-fill`
  的 alpha 从 0.4 提到 0.62 一档）。代价：玻璃感变弱，八张卡整体更"实"。
- **C｜承认它是画的一部分**：把这 2/16 处按「10.5px 元信息小字」豁免，文档写明
  AA 只对正文与卡说明（≥4.76）成立。代价：明知不达标还写进去，下次别人会当它是装饰。

我的建议是 B：它动的正是制造问题的这一层（卡面玻璃），不牺牲画的露出，也不豁免标准。

- 用户真身设置 `AppData/Roaming/mochen-ai/appearance.json`：**这一轮被我的探针写过，已还原并逐字段核过**
  （sha256 回到 `f5628b8a…`，793B，`mode: light`、两套 skin 均 `xi-night`、`art: abyss-hall-night`；
  还原后隔 3 秒再算一次仍是同一个值）。
  ⇒ **一条新知识，别再踩**：自起实例传了 `--user-data-dir=<临时目录>` 并**不会**把这份设置隔开——
  主进程是照 `appData` 拼路径写的，于是探针里每一次 `appearance.update()`（换深浅、换皮）
  都直接落到了用户真身的那份文件上（当场飘成 `mode: dark` + `light.skin: xi-day`）。
  以后要拿真机实例改设置做实验，要么先备份再当场还原（这次就是这么救回来的），
  要么走不落盘的「整窗预览」那条通路；`--user-data-dir` 不是隔离开关。
  全程只起/只杀我自己的 9234 进程，没有碰他自己在跑的 9222（PID 4056）。
  **一处残留风险如实报**：他那台实例如果是在飘之前启动的，内存里仍是原来那一套，
  下次他在外观页点任何一项都会把内存值写回盘；如果他觉得界面与设置不符，重启一次墨宸即可对齐。
