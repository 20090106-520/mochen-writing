## 一、可直接吸收的开源资产（按性价比排序）

### ★1. zenstory-ai/oh-story-claudecode — 网文写作 skill 包（MIT，约 6.7k star）

**这是本次扫描里最该看的一个**：它把「职业网文作者的方法论」拆成 13 个可执行 skill，
而不是一堆提示词。搜索快照里明确写着它「不是提示词合集：内置确定性 verifier、
写正文前会阻断的 Reference Gate、分层的上下文状态管理」。

| Skill | 做什么 | 对墨宸的价值 |
| --- | --- | --- |
| `story-deslop` | **去 AI 味**：检测并清除 AI 写作痕迹，附 `banned-words.md` 禁用词表 + 三遍去AI法 + 改写范例库 | ★★★★★ 墨宸缺一个**本地确定性**的文风体检。纯规则、零 API 成本、可直接做成「审核检查」页签的一等功能 |
| `story-review` | 4 Agent 多视角对抗式审稿 + 番茄/起点/知乎评分标准 | ★★★★ 对应墨宸「审稿」档案，但它是**多视角打分**而不是单点挑错 |
| `story-long-analyze` | 拆文：黄金三章、爽点密度、钩子类型、节奏评分 | ★★★★ 墨宸可做「导入对标 → 生成拆解报告」 |
| 追踪体系 | `伏笔.md`（埋设/回收状态表，跨卷）、`时间线.md`（故事内时间线，全书）、`角色状态.md`（章节级快照） | ★★★★★ 墨宸左栏有「时间线」导航，但**没有伏笔台账这种可查的数据结构** |
| `story-long-scan` | 扫榜（起点/番茄/晋江/七猫/知乎盐言） | ★★ 依赖联网抓取与登录态，隐私与稳定性成本高，**建议不做** |
| `story-cover` | 封面生成（GPT-Image-2 出图） | ★★★ 需要图像模型账号 |
| `browser-cdp` | CDP 复用登录态抓数据 | ★★ 我们自己就在用 CDP 做真机验收，这块能力已有 |

它的文件结构思路也值得抄一句：**「对话只负责创作，不负责记忆」**——设定、大纲、正文、追踪分文件维护。
这与墨宸现在「小说大脑 / 故事规划 / 写作 / 时间线」的分栏是同一个方向，墨宸只是还没把它们接成闭环。

协议：MIT（可借鉴、可改写，但**若直接搬词表/文案必须注明出处**，见 `../../ATTRIBUTION.md` 的做法）。

### ★2. ydsgangge-ux/dramatica-flow（190 star）

Dramatica 叙事理论 + 5 层 Agent 管线，卖点是**因果链管理、多线叙事、伏笔追踪**。
墨宸的「总编」档案职责里已经写了「伏笔登记」，但那是提示词里的一句话，**没有落地结构**——这个项目是那一句的实现参考。

### ★3. john-paul-ruf/novel-engine（开源免费）

7 个 AI Agent 的完整编辑流水线（从选题到成稿），支持 Claude / Codex / Ollama。
架构参考价值：把「架构 → 写手 → 一致性 → 审稿」拆成**有明确交接物的多个角色**，
墨宸现在的六档案是同一思路，但每个档案只产提案，**没有「交棒」概念**。

### ★4. MrCuriosity74/AI-Novel-Writer

灵感 / 角色 / 世界观 / 大纲 / 章节 / 审稿 / 修稿 组织成可控流程，Windows/macOS 桌面版，接 Ollama。

## 二、AI 编程软件侧：可借鉴的**机制**（不是照搬工具）

Cline / Roo Code / OpenCode / Aider / Continue / OpenHands / OpenHands SDK 的横评结论（搜索快照）里，
有三条机制墨宸还没做：

| 机制 | 谁在做 | 墨宸现状 | 建议 |
| --- | --- | --- | --- |
| **Plan / Act 双模式** | Cline、Roo Code | 墨宸直接进 Act：Agent 提一个 diff，人批 | 加一个「先出改稿计划、人点头再动手」的 Plan 阶段。**长篇改稿风险最高的地方就是这里** |
| **上下文原语**（`@file` / `@folder` / `@url`） | Cline | 墨宸有「挂入素材」与 `pinned` | 已具备，可加 `@章节` / `@人物` 快捷引用语法 |
| **多 provider + 本地模型（Ollama）** | 全部开源 Agent | 墨宸只有一个 OpenAI 兼容 `baseURL` | 加 Ollama 支持 = **完全本地、零 API 成本**，对隐私敏感作者是卖点 |
| **每次动作可回滚** | Aider（git 自动提交） | 墨宸刚补上改稿历史（`.mochen/changes`） | 已具备，且比 Aider 的方案对非 git 用户更友好 |
| **PR 式自动检查** | Continue（`.continue/checks`） | 无 | 太工程化，暂不建议 |

## 三、模型选择侧的事实（用户自己配 API 时的依据）

## 五、界面与体验（用户点名「顺眼、精细、好看、流畅」）

本轮已修：改稿历史浮层（列表被压扁、主操作掉出折叠线、缺计数 chip）。
**仍在台账上的**：

- `.mochen/changes` **没有保留策略**（历次改稿全留在盘上，没有淘汰/清理）
- **两处「渲染在、够不着」的死面板**（2026-10-06 批次 5-③ 修掉字数那一处）：
  App.vue 曾为导出与字数各挂一个本地 ref，而 layoutStore 里那份的 action 零调用方——
  两份状态、零个写者。**导出**在批次 5-② 真机上撞出来（EPUB 因此差点交付成够不着的功能），
  **字数**本轮同族修掉。已加推导式守卫 `components/dead-panel-entry.test.ts`：
  App 模板里每个 `:visible` 都必须有写者（本地 ref 要有赋值，store 那一格要有动作且动作在别处被调过）。
  批次 5-④ 又补了第二层：**「有写者」不等于「用户够得着」**——把入口按钮整块删掉，写者还在、
  第一层守卫全绿，而面板从此在界面上消失；现在额外要求每个走 store 的面板，
  要么在某个模板里真的绑到了它的开启动作，要么在 `PanelShortcutId` 里（键盘也算入口）。
  **笔记面板不算这一类**——它有真写者（`panelShortcut` 里的 case，走键盘快捷键），
  守卫里有一条反向钉专门防「为了统一风格把它搬去 store 那一格」。
- **主题旧别名层**（2026-10-06 批次 5-③）：约 250 处样式消费的
  `--surface` / `--dropdown-bg` / `--border` / `--text-muted` 等**全仓从未定义**，
  各自靠硬编码兜底 ⇒ 浅色主题下十一个面板深字压深底、暗色主题下六个浮层浅底浅字。
  修法是在 `appearanceThemeRuntime` 一处把 13 个别名定义出来（铁律 6：不逐个改那 250 处）。
  已加 `composables/theme-token-guard.test.ts`：消费了却没定义的变量一律报出来。
- **`appearance:save` 存不下来任何东西**（2026-10-06 批次 5-④ 修掉）：
  `{ ...this.settings, ...patch }` 只解顶层，嵌套的 `light` / `dark` 仍是 Vue 响应式代理，
  Electron 在 IPC send 端做结构化克隆时当场抛 `An object could not be cloned.`
  ⇒ 用户改任何外观设置都弹回原样。修法 `toRaw`（与 5-② 的 EPUB、`saveMeta` 同一条口径）。
  真机验法是「改设置 → 重启 → 再读」，因为盘上那份以前是诊断时 bridge 直调写的，不是 UI 存的。
- **守卫本身会骗人**（2026-10-06 批次 5-④ 一并记下，这条比上面几条都重要）：
  本项目此前的变异脚本用 `execFileSync("corepack", …)` 起 vitest，**那在 Node 侧压根起不来**
  （`corepack` 只是 PowerShell 的 shim，磁盘上没有同名可执行文件，`spawn` 直接 `ENOENT`），
  而脚本里的 `catch { return { red: true } }` 把「进程没启动」一律读成了「测试红了」。
  于是批次 5-②、5-③ 报的「EPUB 16 条全红 / 卷纲 21 条全红 / 死面板 6 条全红 / 主题 8 条全红」

  四个缺口已在批次 5-④ 补齐。**立下的纪律**：变异脚本必须①每轮先跑基线、
  ②测试进程起不来就 `process.exit(2)` 直接退出，不给「没跑」冒充「全红」的机会。

## 五之二、批次 4-①：Plan 阶段（2026-10-05 完成）

对标 Cline 的 Plan/Act。落地时撞上的第一个问题不是 UI，是**「闸该住哪」**：

- **做成 `writeVerdict` 的第六种判决 `{ kind: "plan-mode" }`，不另开第四个闸。**
  写闸的真身本来就是 `contracts/permission.ts` 的 `writeVerdict`——主进程批准提案、工具宿主放行
  `write_doc`、渲染层提案卡提示，三处共用同一份。另开一个闸就是第二个真身，
  迟早出现「主进程放行了、卡上还在劝你切档」。判决里加一个分支是唯一的加法。
- **plan 判决排在所有档位判据之前**：它比权限档更硬。先报「你切到只读档就能批」，
  用户切完发现还是被拒——那按了没用的按钮比不给更坏（spec §2.7）。
- **拒绝理由必须说下一步**：「切到『直接动手』后就能批」，而不是干巴巴一句被拒。
- **同时要改提示词，不只是加闸**：闸只在模型已经想动手时拦得住，而**模型看不到闸**。
  不先告诉它，它会照常起草、再吃拒、换个写法重试几轮——白烧 token。
  所以 `agent-service` 的 `defaultPromptFor` 在 plan 档追加 `PLAN_MODE_INSTRUCTION`，
  要求它只把打算讲清楚（改哪几篇、每篇改什么、为什么），编号列出。
- `workMode` 字段**必填无默认**（与 `startTurnInputSchema` 里那两枚每轮开关同一条理由）：
  少传就会悄悄按「直接动手」发出去，真机上「闸坏了」与「用户没开计划」分不开。
  老书的兜底只住在 `workModeOf(meta)` 一处。
- 提案卡上那颗按钮是**独立的 `switch-work-mode` 分支**，不复用 `switch`（权限档）：
  它点的不是同一个开关，复用会被装配处接到权限档菜单上。这条是接线测试（`work-mode-wiring.test.ts`）抓的。
- **未在真机上走通的一条（如实记）**：提案卡那枚「切到直接动手」按钮需要一条 pending 提案才能触发，
  本机 API 停在 mock、桩已停，没有现成的提案卡。判定层与跨判定交叉验证
  （「切完真的能批」）单测覆盖充分，但**按钮本身没在真屏幕上点过**。

## 五之三、批次 4-②：审稿多视角打分（2026-10-05 完成）

台账第 4 行下方那句「审稿多视角打分」的落地口径，**与本仓既有边界一致**：

- 左栏「一致性 / 剧情 / 逻辑」三项**要调模型**（烧 token、要等、还得联网），所以至今
  **只预填一句提问，不打分**——这是它们的既有口径，没动。
- 新增的右栏「审稿打分」是**纯本地统计**：句长 / 段落节奏 / 对白占比 / 套话密度四个维度，
  全部从正文数出来，查表即得、零成本、离线可用。套话那一项**复用去 AI 味那份词表**。
- **分数的语义与诚实边界**（这两条是刻意设计的，不是将就）：
  - 分数量的是「写法有多常规」，**不是质量**。60 是中性基准、**不是及格线**，
    分数条上画一道 60 的刻度就是防用户误读；文案层禁止「合格 / 通过」等质量判断词。
  - **剧情是否成立、人物是否一致——本地数不了，就在浮层里明写「给不出分」**，
    不给假分，更不并进分数条（并进去会被读成打了 0 分）。
  - 交读数给 AI 那一步**只预填不自动发送**，且指令明确写「不要给分数」。

两条真机教训（静态扫不出来的那种）：

1. **同一组数不许判两次**。`hint` 与分数各判一次判据，就出现「54 分 / 明显偏出」
   配一句「还算清爽」。修法：话术跟着分数那一支的判据走（`paragraphHint`）。
2. **`position: sticky` 只保证不滚出视口，不保证不压内容**。最初「整个浮层滚动 + 按钮 sticky」，
   真机截图里按钮浮在列表中间，把后两个维度和「算不出那两项」全压住。
   改成三段式（头固定 / 中间自己滚 / 按钮在滚动区外）。
   **连带一条量法教训**：第一版真机断言量的是「按钮在浮层内」，改结构后照样返回 true——
   几何相交不等于被遮住。要量**可视区内**的重叠。

## 五之四、批次 5-①：时间线一致性检查（2026-10-05 完成）

台账第 3 行的落地。此前左栏「时间线」只是个文档树入口，**没有一处能查时间对不对得上**。

- **一条时间线就是一篇普通文稿**（`timeline/` 下的 .md），日期走 frontmatter `date: YYYY-MM-DD`；
  复用文稿层就自动有了左栏树、AI 可读写、搜索、备份与改稿历史。
- **只报算术上确凿的三类**：`unreadable`（日期写坏，显式报 + 回显原值，绝不悄悄跳过）、
  `unsorted`（两篇先后写反）、`gap`（正文说「三天后」而日期只隔两天）。
- **「查不出的」明写**：谁该不该在场、事件该不该发生——判断不是算术，浮层底部虚线框单列。
  沿用批次 4-② 立的同一条纪律：本地算不出的宁可承认，不编。
- **「日期写坏」与「没写日期」分开**：前者琥珀实边 + 报问题，后者虚线 + 「未排期」。
  把「还没排期」当成错，作者会为了消警告去乱填日期。
- 住 contracts（主进程扫盘 + 渲染层显示要同一份）；读盘另立 `useTimelineStore`
  （useBookStore 已 750 行，且它扫的是**全书**、不随当前标签变，职责本就不同）。

两条值得留档的教训：

1. **日期算术不许将就**：2 月 30 日不是「3 月 2 日的前一天」——`dayOfYear` 必须先过真日期校验，
   否则会凭空造出一条不存在的矛盾。任一认不出就回 `null`，**绝不给 0**（0 会被当成「同一天」）。
2. **真机撞出一个真 bug**：`checkTimeline` 原先对相邻两篇的 `[to, from]` 两边都试，
   中间那篇既当下篇被比、又当下一篇的 `from` 再比一次 ⇒ 报出一条假矛盾、且同一篇被列两次。
   改成「只看当前篇、只跟紧邻的上一篇比」。**相邻两篇的关系只能有一份实现**——
   这和批次 3「同一判定只有一份实现」是同一条铁律在不同层面的体现。

## 五之五、批次 5-⑤：「添加模型」重做（2026-10-06 完成）

台账第二节里那句「**多 provider + 本地模型**」此前只做了 Ollama 一半（一个全局地址），
另一半——**真的能切供应商**——一直是缺的。本批补上，对标 Qoder 的添加模型弹层。

三条要记的：

- **供应商与 API 类型是「两个写死禁用的下拉」**：卡片上那句「OpenAI Compatible」是
  `ProviderSettings.vue` 里的硬编码字面量，`contracts` 里**连一个供应商枚举都没有**。
  「不能切换、不能快捷使用」说的就是这个。切供应商带出来一个新坑：
  **不是所有 OpenAI 兼容端点都收 `Authorization: Bearer`**（小米 MiMo 官方用 `api-key`），
  所以 `authHeader` 是一等字段而不只是「多几行预设」。
- **地址从全局一份改成按连接分份**：`config.json` v2 `{baseURL, profiles}` → v3
  `{connections, profiles}`，密钥从 `secrets.enc` 一份改成 `secrets/<连接id>.enc`。
  「同时存着 DeepSeek 和 OpenAI、随时切」是这轮改动的目的；不分开就没法做到。
  **`LEGACY_CONNECTION_ID` 用固定值不用随机数**——随机 id 会让「第一次迁移后改的密钥」
  在下次迁移后读不到。
- **不做 Qoder 的硬校验，改软校验 + 状态常显**：用户本机没有可用 Key，硬校验会直接把他卡死。
  但「不校验」也不行——此前保存**完全不校验地址**（`http://…/v1http://…/v1` 也照样存下来并启用），
  且「连不上」只在校验那一刻出现、点保存就消失，用户看着像配好了。
  折法是**存照存，存完立刻体检一次，三档结果常显在卡片和对话框上**。

  「API 类型」那一行**从禁用下拉改成一行只读说明**：底层只实现了 Chat Completions，
  摆个能点没用的下拉就是装样子。Responses API 做了之后才配把它变回能切的。

### 这一批撞出来的通用教训

1. **「按地址反查」是配多份配置时的经典错**。新增连接后对话框是拿 `baseURL` 回头 `find` id 的，
   而同一家开第二个账号（个人号 + 企业号）时地址一模一样 ⇒ `find` 先命中前一条 ⇒
   **模型挂到用户没在配的那条连接上**。修法是让主进程把 id 一起回传
   （`ProviderSaveResult extends ProviderView`，加长而非嵌套，既有消费方零改动）。
   真机上端到端复现过：加第二条同地址连接，两条卡片各挂各的模型、各带各的密钥掩码。
2. **`.vue` 里死 import 只有 eslint 逮得到**（`tsc` 完全看不见 `.vue`，`vue-shim` 声明成 any）。
   同一批还差点把 `OLLAMA_FILL_LABEL` 变成孤儿常量（contracts 里没人用了，组件里写了字面量）——
   那种「常量还在、内容被复制一份」的漂移，比删掉常量更坏。
3. **`.vue` 里 `<select>` 的样式漏了没人会提醒**：`.provider-field input` 有 padding（33px），
   `.provider-field select` 一条规则都没有 ⇒ 浏览器原生高度 19px，同一列里那两格「塌了」。
   **本仓目前没有自动钉控件齐平的守卫**，只能靠真机量。
4. **变异脚本「红」了要看是不是断言红的**（同 5-④ 的升级版）：把 `.superRefine(` 改名会让测试
   **编译期**挂掉，报出来是 `Tests: no tests`——脚本把它当成「杀掉」，其实什么都没证明。
   改函数体（`if (false)`）才是真杀（`1 failed | 17 passed`）。

### 诚实边界（本批**没有**验到的）

- **OpenAI 与 OpenRouter 的 baseURL 本机到境外不通**，只做了 10s 超时探测，**未实测**；
  预设的 `note` 里写明了这一点。国内六家（百炼 / DeepSeek / 智谱 / Kimi / MiniMax / MiMo）
  此前已实测 401 通过，Google Gemini 由官方文档确认。
- **MiMo 的 `api-key` 头没有真 Key 可验**，只能说「按官方文档实现」。
- 新撞到一个口子：**删掉一条连接时，若它正是启用中的那条，会静默留下「一条都没启用」的状态**
  （真机测完自己撞上，靠手动把开关拨回来）。要么删前二次确认，要么删完自动启用剩下某一条。
