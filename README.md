# 墨宸 AI

长篇小说与长文写作的**本地 Agent 桌面端**。Electron 42 + Vue 3 + Pinia，pnpm workspace。
正文、会话、修改记录全在你自己的磁盘上；模型走你配的任意 OpenAI 兼容端点，本仓库不含任何云端服务。

目录名还叫 `深渊写作`，这是故意的——品牌定稿为「墨宸 AI」，仓库与本地目录沿用了旧名。

## 打开就能做的事

- **工作台**：中栏是「对话 + 文档」并排；左栏是作品与章节的导航（卷级大纲在单独的面板里）；上下文占用、
  伏笔、水词、审稿评分、变更历史各有一块面板，都读同一份现场状态，不是摆设。
- **六个墨宸档案**：`墨宸 · 世界`、`总编`、`角色`、`主笔`、`续写`、`审稿`（`packages/contracts/src/agent-profile.ts`）。
  一档绑一条连接一个模型，切档案即切「这条连接 + 这个模型」，切失败的理由摆在界面上而不是静默回退。
- **一轮最多六枚工具**：`read_doc` / `list_docs` / `search_docs` / `propose_patch` / `write_doc` / `web_search`。
  其中只有 `propose_patch` 与 `write_doc` 会产生待写入动作，而写盘必经审批；`web_search` 出网但只读。
  「联网」开关决定的是**这一枚 function 工具有没有出站**：开 = 递 6 枚，关 = 递 5 枚，工具清单同步显示。
  出站只允许一种形状（`{type:"function", function}`）——这是真机 400/422 量出来的教训，
  账在 `docs/superpowers/plans/README.md` 批次 5-㊹ 一节与提交 `ef46153`。
- **插件与技能**：内置插件首次启动种到盘上，用户改过就永不覆盖；有技能市场与技能装载。
- **皮肤广场 8 套**：`汐`（昼阁 / 夜阁）、`书舟`（昼渡 / 夜航）、`灯楼`（晴昼 / 燃夜）、`墨潭`（映日 / 沉雾），
  每套都是带整窗画面的场景画，出厂配色不再单独充当皮肤。画由仓内生成器产出
  （`apps/desktop/scripts/gen-scene-svgs.mjs` + 配色表 `apps/desktop/scripts/scene-palettes.mjs`），
  质量由三道像素闸 G1/G2/G3 盯（`apps/desktop/scripts/check-scene-art.mjs`，跑
  `pnpm --filter @mochen/desktop check:scene-art`；需先 build 并自起一台实例）。
- **中文输入法组合态**（IME）、**思考窗**（按发送到首字之间不再空窗）、**视图过渡与弹簧缓动**——
  这三件都是真机巡检量出来的缺口，不是先设计后实现的。

## 怎么跑

```bash
pnpm install                 # pnpm 由 corepack 提供，版本见 package.json 的 packageManager
pnpm mock-provider           # 本地假模型服务（8787），不联网也能把整条链路跑通
pnpm dev                     # 开发
pnpm build && pnpm smoke     # 构建后起一次真实例做冒烟
```

模型地址与密钥在界面里配（连接 + 档案两层），仓库里没有也不该有凭据文件。
作品目录由你在首次启动时指定；会话 JSONL 与写盘前备份落在作品目录的 `.mochen/` 下，
**永远不进仓库**（`.gitignore` 里有这一条，且写明了理由）。

一条命令串起六道闸，任何一道红就不能提交：prettier 全仓格式、`tsc --noEmit`（6 个类型程序）、
eslint（`--max-warnings=0`）、包边界检查、**单文件 800 行预算**，最后 `vitest run`
（CI 在 Linux 上的干净提交树 `1cb4a29`（2026-10-14 那一轮，两个分支各触发一枚 run，run 页 `38447979538`
与孪生的 `38447928648`）报的数：**315 文件 / 4125 用例**；本机 Windows 在**同一棵树** `1cb4a29`（2026-10-14 02:37）实测
**315 文件 / 4126 passed | 2 skipped**（4128 条注册）。这一跑的 `git status --porcelain` 跑前与跑后各读回一次，两边都是 0 条、
名单当场落盘为空，跑的正是那枚 HEAD 自己（六段码与两段时刻见第五十八节）。顶格两格第一次不必再靠 blob 哈希反推「哪两份文件此刻还没提交」：
上一版这两格绑的是 `a953b12`，那一跑 porcelain 前后各 2 条，而那 2 条正是尚未提交的 README 与门面守卫自己，
只能拿字节对照作出处——第五十七节那套逐条时刻与两枚哈希今天仍然作数，只是不再被这两格引用。
从 2026-10-14 起 Linux 那一格不再是我替 CI 转述的数：两枚 run 各自把 `files=315 registered=4125 passed=4125 skipped=0 failures=0`
写成一条 annotation，无需认证就能从 check-run 的 annotations 接口读到，通路是第五十三节落的 `tools/ci-test-summary.mjs`。
同树对照差的这 1 条不是漂移，而是同一份文件在两个平台各注册几条：win32 分支多注册 3 条、
两枚 `it.skipIf(win32)`（`packages/fs-store/test/changes.test.ts` 的第 247 与 302 行，都是书外软链的守卫）
在 Windows 上不真跑，`+3 − 2 = +1`；Linux 侧 4125 条注册 = 本机 4128 − 3。那笔账由
`tools/platform-test-count.test.mjs` 钉着，改那两个平台分支时它会先红；那两个行号本身由
`tools/readme-provenance.test.mjs` 核对（行号引用闸从 2026-10-14 第五十九节起不住在 claims 了；
锚点定义只在 `tools/platform-anchors.mjs` 存一份，行号一漂移门面就红）。

那本账从 2026-10-13 第五十二节起**不再能只数那一份文件**：第十三道闸（CI 作业名）落地那一刻
`tools/readme-claims.test.mjs` 写到 832 行，被门面自己那条「单文件 800 行预算」当场判红——这是这条预算
第一次红在守卫自己身上，而按 README 的拆法依据（「不共享状态」）搬出去的正是「门禁由哪几段组成」这一族：
现在它是 `tools/readme-gate-composition.test.mjs`（2 道），当时共用的取文本层在
`tools/readme-gate-facts.mjs`。2026-10-14 第五十九节按同一句判据又切了一刀，切因是**余量**不是超限：切之前
`tools/readme-claims.test.mjs` 停在 791/800，再加一条断言就得先红一次门禁——搬出去的是「数有没有出处」那一族
（测试数的树出处、日期附加、run 页 ID 配对、ID 不许藏进引号、按行号点名的锚点），现在它在
`tools/readme-provenance.test.mjs`（11 道），原文件留 7 道，三份共用的取文本层与「反引号十六进制」的取枚正则
（`SHA` / `SHA_G`）都在 `tools/readme-gate-facts.mjs`。所以「门面守卫共几条」要三份文件各自数 `^test(` 再相加
——这一句从 2026-10-14 第五十五节起**有自己的闸**（第十四道，住在 `tools/readme-claims.test.mjs`）：
门面按文件点名的守卫条数必须等于那份文件此刻行首 `test(` 的行数，
带 `git show <rev>:` 的那种历史说法除外——但现役那句不许靠改写成历史说法躲开，现在时的点名剩不到两站当场红。
顶格那两格如今是 `1cb4a29` 上**两侧同树**读回的数，文件数那一格两侧都是 315——上一刀留的那句「拆分后 run 页上的文件数会比
313 多一份，而这句是推的不是读来的」到这里才第一次被读掉。**这一句与上面 quoted 的那份 CI annotation 原文从 2026-10-14
第五十六节起也有自己的闸**（第十五道）：quoted 原文里的 `files=`、`registered=`、`passed=` 与「两侧都是 N」那个 N，
都必须等于顶格那两格读出来的数——第九道只管写成等式的算式且对文件数只钉「两格彼此相等」，
所以把两格**一起**改掉、引用侧原地不动，以前是一条都不红的（M57 量的就是这一条）。

第五十九节那一刀只多了一枚**测试文件**、一条断言都没加，所以顶格两格仍绑 `1cb4a29`——那才是两侧都在零脏项树上有读数的
那一枚，而新树上 `vitest run` 的文件数会比 315 多 1，**这一句是推的、不是读来的**，等下一次两侧都在净树上重读时再决定换不换绑。

第六十节往 `tools/readme-provenance.test.mjs`（11 道）加了 5 道**归属闸**（第十六道），仍然只加断言、不加测试文件，
所以顶格那两格照旧绑 `1cb4a29`。这一道闸管的是门面上一类以前没人看着的话：**「某道闸住在哪份文件」**。
第五十九节把出处那一族整族搬过来之后，门面与两处模块头里「谁核对行号」的说法一次错了三处，而当时十五道断言
一条都不红——第十四道只认「某份 .test.mjs 后面紧跟（N 道）」那种带数的点名，路径闸只认文件在不在，等式闸只认写成等式的算式，
这种不带数、不成等式、文件也确实在场的一句话正好落在三道闸的缝里。现在它的判据是一张唯一登记表
`GATE_ATTRIBUTIONS`（住在 `tools/readme-gate-facts.mjs`，与取文本层同一处）：门面点名过的每一份 .test.mjs
都必须登记在案，登记的那道闸必须在门面上至少有一句把它指到登记的那份文件，而被点名的那份文件此刻必须真有一条
行首 `test(` 的**标题**含着词表里的词——判据落在标题而不是全文，因为 claims 那份搬家说明的正文里同样写着
「按行号点名时那一行必须真含着锚点」，按全文找的话指错的那句照样绿。

门禁的「几道闸」一共有**三处**口径：`package.json` 里 `verify` 的真身、门面正文这一节、CI 页面上那句作业名。
前两处各有各的闸（都在 `tools/readme-gate-composition.test.mjs`，按 `&&` 与 `+` 逐段对表同一张
`VERIFY_KINDS` 登记表），第三处在本刀之前一个字都没人看着——它当时写的是「六路 typecheck + lint +
boundary + budget + 全量测试」，**prettier/格式那一段根本不在里面**，前面十一道闸一条都不红。
现在作业名里 `+` 切出来的每一路都必须是登记表里真在跑的一类、每一类都必须被写到一次，`6 枚 tsc` 那个数
还得等于 `verify` 里的 tsc 段数；这三处任何一处改了写法而另两处没跟上，当场红。

这一句以前写着「当前 215 文件 / 3014 用例」，那个数是冻死的：2026-10-09 的全仓扫描在同一棵树上实跑已经是
217/3037，而写在门面上的数一直没人回头改。测试数没有单一事实源，「用例变多了」这句话就失去意义，
所以这里只留「某一次实测 + 那一次跑的是哪棵树」：上面门禁那两格是在 `1cb4a29` 上**两侧同树**读回的数
（Linux 那格来自两枚 run 页的 annotation，那两枚 run 的 `head_sha` 当场从 JSON 里读回就是已提交的 `1cb4a29`，
Windows 那格跑的是同一棵树且 `git status --porcelain` 跑前跑后各读回一次都是 0 条、名单落盘为空，逐段码见第五十八节），
而门面守卫每往自己身后加一条断言，这两个数就各再落后 1 条——回填不是每刀必做，
做的时候两侧都要从**同一棵树**重读，只 bump 一边会把同树对照又拆掉——这件事现在有自己的闸：
门面里那几处同树说法点名的短哈希必须同一枚，差一枚当场红。要准数请跑 `pnpm test` 看当场输出。

2026-10-12 又补一条更细的教训：本机在 2026-10-11 读到过 **328 文件 / 4261 用例**，那棵树当时压着另一条会话
**未跟踪**的用例文件（第二天回读数得出 25 个未跟踪 `*.test.ts`，与两数之差 24 同量级；那一跑没有复现，所以只说同量级）。
所以「N 文件 / M 用例」这句话**必须连着「跑在哪棵树上」一起说**——干净提交树上的数以 CI 为准，
本机要报这个数得先当场读回 `git status --porcelain` 是 0 条（共用一棵工作树时本机数天然偏大）。原文与逐条回读见
`docs/superpowers/plans/2026-10-09-full-scan-report.md` 第二十三节。

「闸」这件事在 2026-10-09 之前是半真的：闸是真闸，但**没人强制跑**——本机既没有 CI（`.github` 目录不存在），
也没有 git 钩子（`core.hooksPath` 为空，`.git/hooks` 里只有 sample 文件），全靠人记得敲一次 `pnpm verify`。
现在 `.github/workflows/verify.yml` 在每次 push 与 pull_request 上跑同一条 `pnpm verify`
（`--frozen-lockfile` 装依赖，一步都不许包进管道——管道会把退出码换成最后一个命令的码），
并由 `tools/ci-gate.test.mjs`（6 条）把"CI 在场、跑的是整条 verify、不吞码"这三件事钉成断言。
本机仍然要自己跑：CI 只能证明推上去的那棵树是绿的。

几条反复被真机打脸的硬规矩，改代码前先读：

- **一个出站字段名只在一处映射**。报不出出站字段名的控件不许进界面。
- **失败必须可见**。吞掉异常换一次「看起来正常」的白屏，比报错严重。
- **断言要能证明它会红**。新功能一律先反向用例（先红）再实现（转绿），提交前自跑一次变异。
- **行数预算是硬的**。贴到 800 行就拆，拆的依据是「不共享状态」，不是「注释太多」。
